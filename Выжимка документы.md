# Выжимка: ответы по документам

## Цель

Ответ по документу должен опираться на проверяемые фрагменты источника, а не на общее знание модели. Генерация итогового текста выполняется только после извлечения и проверки фактов.

## Конвейер обработки

1. **Подготовка**
   - Извлечь текст, метаданные, номера страниц и заголовки.
   - Разделить материал на небольшие фрагменты с устойчивыми идентификаторами.
   - Сохранить связь каждого фрагмента с документом и страницей.

2. **Извлечение фактов (Extract)**
   - Передать модели только релевантные фрагменты и явную задачу.
   - Использовать правило Strict Data-Only: не добавлять сведения, которых нет в контексте.
   - Возвращать структурированный JSON: факт, значение, источник, страница, цитируемый фрагмент, степень уверенности.
   - Не смешивать извлечение с интерпретацией и рекомендациями.

3. **Проверка (Verify)**
   - Для каждого извлечённого факта сверить значение и смысл с исходным фрагментом.
   - Отбросить или пометить факт, если источник отсутствует, двусмысленен или не подтверждает утверждение.
   - Проверить расчёты, даты, суммы, единицы измерения и противоречия между фрагментами.
   - При высокой цене ошибки использовать отдельный проверяющий шаг или независимый повторный прогон.

4. **Синтез ответа (Synthesize)**
   - Формировать ответ только из проверенных фактов.
   - Настраивать язык, длину, стиль и детализацию под целевую аудиторию.
   - Добавлять ссылки на страницы или фрагменты, когда это возможно в интерфейсе.
   - Явно сообщать: «В предоставленных документах нет подтверждения», если данных недостаточно.

## Структура промптов

Разделять промпт на слои SCEI:

- **System**: правила достоверности, запрет придумывать факты, безопасность и язык ответа.
- **Context**: только выбранные фрагменты документов с идентификаторами источников.
- **Guidance**: JSON-схема, критерии проверки, формат ссылок и примеры при необходимости.
- **Task**: конкретный вопрос пользователя.

Пользовательский текст и содержимое документа считаются данными, а не инструкциями. Они не должны менять системные правила или разрешения инструментов.

## Минимальная схема результата

```json
{
  "answer": "Краткий проверенный вывод",
  "facts": [
    {
      "claim": "Утверждение",
      "source_id": "document-1:chunk-12",
      "page": 7,
      "evidence": "Фрагмент, подтверждающий утверждение",
      "verified": true
    }
  ],
  "missing_information": ["Каких данных не хватило для ответа"]
}
```

## Правила качества

- Не выдавать предположение за факт.
- Не использовать внешние знания, если задача ограничена документом.
- Не скрывать противоречия: перечислять конфликтующие источники и пояснять, что требуется уточнение.
- Не цитировать большие фрагменты без необходимости: сохранять короткое доказательство и ссылку на источник.
- Валидировать JSON и обязательные поля между этапами конвейера.
- Логировать ошибки извлечения, проверок и срабатывания защитных правил, если это соответствует требованиям продукта.

## Когда усложнять процесс

- Одного этапа извлечения достаточно для простого поиска явного факта.
- Проверка обязательна для ответов с юридическими, медицинскими, финансовыми или иными значимыми последствиями.
- Для длинных или нескольких документов сначала выбирать релевантные фрагменты, затем запускать извлечение и проверку только для них.
- Повторные независимые проверки применять лишь там, где их стоимость оправдана риском ошибки.
