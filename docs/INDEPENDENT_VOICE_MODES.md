# Независимые режимы v3 и Voice ID

Дата изменения: 2026-09-27. Реализовано по одобренному плану разделения режимов.
Актуальный сценарий заменяет прежнюю обязательную связку v3 + Voice ID из
`METRIC_KWS_V3_ACTIVATION.md`. Исторические отчёты обучения и первоначальной
интеграции сохранены отдельно.

## Настройки и поведение

Открыть **Настройки → Голос → Активация и звук**. Выбор «Способ активации»:

| Способ | Voice ID выключен | Voice ID включён |
|---|---|---|
| Обычный голосовой ввод | Команда без слова активации | Команда без слова активации, с проверкой владельца |
| Активация по имени | Прежний путь по текстовому имени | Тот же путь с проверкой владельца |
| Персональное слово v3 | Записанное слово → сигнал → отдельная команда | Слово + проверка владельца → сигнал → отдельная команда с новой проверкой владельца |

Voice ID — самостоятельный переключатель. Запись слова не включает Voice ID,
запись голоса не включает v3 и не меняет способ активации. Оба профиля можно
подготовить при выключенных функциях. Смена имени ассистента и выключение/повторное
включение Voice ID сохраняют профили.

В режиме v3 без Voice ID **отдельной проверки владельца нет**. Это не означает,
что слово любого человека обязательно совпадёт с записанным embedding: точность
распознавания зависит от модели и записи. KWS не заявляется заменой Voice ID.

При включённом Voice ID без исправного профиля команды блокируются с сообщением
о необходимости записать голос. Отсутствие/повреждение слова или модели при
выбранном v3 также блокирует активацию. Приложение не включает вместо него другой
способ. После удаления слова выбор v3 сохраняется с состоянием «не записано»;
пользователь может записать слово или сам выбрать другой способ.

«Записать слово» означает запись через микрофон. После успешной записи v3 локальное
распознавание заполняет поле **«Имя ассистента»**, и имя появляется в хедере вместо
`AI Assistant`. До первой записи/правки отображается прежнее `AI Assistant`.
Поле редактируется отдельно: **сохранение нового текста меняет только хедер**,
не меняет отпечаток слова, Voice ID, порог, способ активации или открытое окно команды.
Чтобы изменить само произносимое слово v3, нужна кнопка «Перезаписать слово».
Отдельное поле «Слово для режима „Активация по имени“» сохраняет прежнее назначение.
Подробности и результаты этого дополнения: [ASSISTANT_DISPLAY_NAME.md](ASSISTANT_DISPLAY_NAME.md).

Функции работают в существующем голосовом режиме. Для непрерывного обычного ввода
после ответа используется существующая настройка диалога. Диктовка в черновик,
календарные поля и прерывание ответа сохраняют своё назначение; Voice ID, если
включён, применяется и к этим входным сегментам. v3 обслуживает ожидание слова,
а не превращает каждый сегмент диктовки в попытку активации.

## Запись и хранение

- **«Записать слово»**: при остановленном голосовом режиме/конференции нажать кнопку,
  дождаться «Идёт запись», произнести одно слово и сделать паузу. Voice ID не нужен.
- **«Записать голос»**: аналогично записать короткую фразу обычным голосом. Имя
  ассистента и слово v3 не нужны. Запись не включает переключатель Voice ID.
- Используется прежний AudioRecord, AEC/NS/VAD и MicrophoneCoordinator; отдельный
  постоянный микрофон не создаётся. Таймаут захвата — 12 секунд.
- Исходное аудио не сохраняется; возвращённый PCM очищается после обработки.
  Отпечатки сохраняются в отдельных приватных файлах без резервного копирования.
  Распознанное имя хранится отдельно в настройках `assistant_display_name` для хедера.
- `metric_kws_profile.bin` теперь имеет собственную версию профиля. Кодек пишет
  формат 2 и читает формат 1: SHA/параметры модели, embedding и дата сохраняются,
  прежняя привязка к версии Voice ID отбрасывается. При чтении старый файл не
  переписывается; следующая запись использует формат 2. Повреждённые данные и
  несовместимая модель не принимаются.
- `voice_profile.bin` сохраняет прежний формат. Исправный существующий профиль
  работает после обновления. Профиль, ранее удалённый старой версией приложения,
  восстановить без новой записи нельзя.
- Отмена до сохранения и неудачная обработка не заменяют старый профиль. Для
  Voice ID ошибка сохранения настроек после записи файла восстанавливает прежний
  файл. Отмена после завершённого сохранения не является откатом: экран показывает
  фактическое состояние.
- При регистрации слова v3 пустой/ошибочный результат распознавания не заменяет
  прежние слово и имя. Если запись имени в настройки завершилась ошибкой после
  сохранения нового отпечатка, восстанавливается прежний профиль слова.
- Удаление слова не затрагивает голос. Удаление голоса не затрагивает слово и не
  меняет выбранные переключатели. При включённой удалённой функции требуется
  повторная запись или её явное выключение.

## Изменения реализации

`PersonalKeywordActivation` больше не имеет зависимости от проверки говорящего
или настроек Voice ID. Он проверяет качество записи, модель и совпадение слова.
`PersonalKeywordWakeSession` выполняет отдельную проверку владельца только при
включённом Voice ID: и для активации, и для последующей команды. При несовпадении
слова ASR и проверка владельца не запускаются. Отдельный запрос готовности
включённого Voice ID может предшествовать KWS; он не вычисляет embedding голоса.

Существующие ключи DataStore и выбранные пользователем режимы сохраняются.
Добавлен `audio_policy_revision`, меняющийся при смене условий ввода или профиля.
Снимок этих условий проверяется до передачи команды. В активном голосовом режиме
изменение условий останавливает текущий захват и запускает нужный вариант снова;
старое окно команды и очередь больше не авторизуют новое обращение.

Настройки выключенного v3 читают метаданные профиля без загрузки ONNX. Нативная
модель загружается при записи/явном выборе v3 либо его обработке. При выключенном
Voice ID его извлечение embedding и проверка владельца не вызываются. Уже
созданные нативные объекты могут оставаться в памяти до закрытия их владельца;
это не обещание выгрузки модели при каждом переключении.

Веса v3, Kotlin MFCC и dev-порог `0.5827946662902832` не менялись.
SHA-256 ONNX: `5d4828f3a8aea2eff1f677b1ab9c51acef0aa732c55f1c425d8d95da41d009a2`.
Изменено описание политики только в метаданных основного приложения. Архив
обученной модели, checkpoint, тестовые PCM и лицензионные материалы сохранены.
`activation_validated` остаётся `false`: полевых испытаний микрофона пока нет.

## Автоматическая проверка

Итог этапа разделения режимов от 2026-09-27, до дополнения отображаемого имени:

ошибок и пропусков нет. Lint: 0 ошибок, 49 предупреждений, 7 подсказок.
Android-проверки выполнены на выделенном эмуляторе API 34 / x86_64. APK установлен
на этот эмулятор; холодный запуск MainActivity успешен, при последующей проверке
экран активен и процесс жив, журнал сбоев пуст. Проверены 41 численный сигнал
и 144 решения против Python; максимальная ошибка embedding — `4.5597553e-6`.

APK: `app/build/outputs/apk/debug/app-debug.apk`, 722 677 651 байт.
SHA-256: `7e626644720e0be28cbada85d5922c4d3be01ca2a337432e1b22adef26babc87`.
Исходные результаты и SHA исходников: `docs/validation/independent_voice_modes/`.

Количества тестов, контрольные суммы APK и ссылки на исходные результаты того этапа:
`INDEPENDENT_VOICE_MODES_VALIDATION.json`.
Проверки обновлённого APK с именем в хедере описаны в `ASSISTANT_DISPLAY_NAME.md`.

Проверки включают:

- самостоятельную регистрацию слова без зависимостей от Voice ID;
- таблицу принятия/отказа при включённой и выключенной проверке владельца;
- отсутствие вызовов Voice ID в самостоятельном v3 и KWS в прежнем маршруте;
- блокировку недоступного выбранного режима без автоматической подмены;
- таймаут, старую очередь, изменения настроек во время проверки/ASR/сигнала;
- совместимость старого кодека и проверку повреждения профиля;
- сохранность голоса при смене имени/переключателей и откат ошибки сохранения;
- реальные ONNX/JNI/MFCC на эмуляторе и сравнение с Python;
- Compose: все четыре сочетания, отдельный режим по имени, удаление и отмену.

Проверки владельца в тестах маршрутизации используют контролируемый заменитель.
Они проверяют программные условия, а не точность биометрии. Ускоренный тест
обработки трёхчасового PCM также не является трёхчасовым испытанием телефона.

Автоматические проверки воспроизводятся из корня проекта командой ниже.
Для неё нужен заранее запущенный тестовый эмулятор с указанным serial.

```powershell
$env:ANDROID_SERIAL = 'emulator-5580'
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.package=com.example.aiassistent1.audio' '-Pandroid.testInstrumentationRunnerArguments.metricKwsAssets=metric_kws_ru_v3' --no-configuration-cache --offline --console=plain
```

Connected-тесты используют тестовую установку и могут удалять её данные.
Не направлять эту команду на пользовательский телефон с рабочими чатами.

## Проверка на физическом телефоне

Статус: **не выполнена в этом этапе**. APK и эмулятор не подтверждают микрофон,
ложные активации, батарею или работу конкретного телефона с выключенным экраном.

1. Установить `app/build/outputs/apk/debug/app-debug.apk` обновлением, сохранив данные.
   При несовпадении подписи не удалять приложение ради установки. Проверить чаты
   и работоспособность обычного голосового ввода с обоими режимами выключенными.
2. Выключить Voice ID, записать слово и выбрать v3. Включить голосовой режим,
   произнести слово, дождаться сигнала и произнести отдельную короткую команду
   в течение 10 секунд. Слово не должно появляться как сообщение в чате.
3. Проверить неправильные/похожие слова. Они не должны запускать команду.
   При выключенном Voice ID отказ чужому голосу не является обязательным условием.
4. Выбрать обычный ввод. Записать голос, затем включить Voice ID. Произнести команду
   без имени и слова v3. Проверить владельца и другого человека. Ожидаются принятие
   владельца и отказ другому человеку; записать фактические ошибки.
5. При сохранённом голосе снова выбрать v3. Проверить четыре комбинации
   «правильное/другое слово × владелец/другой человек». Успешная активация ожидается
   только при правильном слове владельца. Отдельно: владелец произносит слово,
   другой человек — команду после сигнала; ожидается отказ команды.
6. Выключить Voice ID, сохранив v3: слово должно работать без повторной записи.
   Включить Voice ID обратно: его профиль должен остаться готовым. Сменить имя
   ассистента и проверить, что оба записанных отпечатка сохранены.
7. Выбрать активацию по имени и проверить прежний сценарий «имя + команда».
   Повторить с Voice ID и без него. Затем снова выбрать v3 без перезаписи слова.
8. После сигнала ждать 11 секунд и произнести обычную команду без слова: требуется
   новое слово. Переключить режим между сигналом и командой: прежнее окно закрыто.
   Проверить переключение с обычного ввода на v3 во время речи: старый сегмент
   не должен отправиться как команда нового режима.
9. Начать перезапись каждого профиля и отменить до окончания захвата; повторить
   с закрытием настроек и с тишиной до таймаута. Прежний профиль должен сохраниться,
   микрофон — освободиться. Проверить отказ разрешения, занятую конференцию и ввод.
10. Удалить только слово: голос остаётся. При выбранном v3 появляется состояние
    отсутствующего слова, другой режим сам не включается. Перезаписать слово,
    удалить только голос: слово остаётся. Выключенный Voice ID не мешает v3.
11. Перезапустить приложение и проверить сохранность режимов/профилей. Проверить
    возврат после TTS, фон, выключенный экран через 1 и 5 минут, переход в конференцию.
    Непрерывное ожидание и расход батареи измерять отдельными прогонами.

Для сопоставимой пробы: по 20 повторений правильного слова, похожих/других слов
и, где возможно, правильного слова другим человеком. Между активациями без команды
ждать не менее 11 секунд. Внутри серии не менять профиль и порог. Записать телефон,
Android, условия, режимы, число попыток, пропусков, сигналов и ошибочных сообщений.
