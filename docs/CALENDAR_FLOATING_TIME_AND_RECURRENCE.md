# Местное время события и повторения

Дата: 20 октября 2026 года.

## Поведение для пользователя

В редакторе календаря и в редакторе черновика доступны независимые настройки:

- **Фиксированный момент** — обычное событие сохраняет конкретный момент времени. У новой серии сохраняется исходный часовой пояс для расчёта повторений.
- **Всегда по местному времени** — сохраняются местные дата, начало и окончание без привязки к часовому поясу. Например, «Зарядка, 09:00» остаётся на 09:00 при смене пояса.

При показе и поиске floating-событие интерпретируется в текущем поясе календаря; по умолчанию это пояс телефона. Выбор другого пояса меняет вычисляемые моменты времени, но не записанные 09:00 и правило повторения.

Режим floating доступен и для однократного события. Повторение выбирается отдельно:

- один раз;
- в выбранные даты, с вводом списка и добавлением дат через календарь;
- каждый день;
- по выбранным дням недели, Пн–Вс;
- каждые N дней, недель или месяцев, N от 1 до 999.

Дата события задаёт начало расписания. В ручном редакторе она берётся из выбранного дня календаря; в черновике редактируется полем даты. Выбранные дополнительные даты должны быть не раньше начала. В режиме выбранных дат отображаются только выбранные даты: начальный день не добавляется автоматически.

Для повторений доступны «Без окончания» и «До даты». Последний день включается в расписание по дате начала повторения. Пустые дни недели, неправильные даты и интервалы блокируют сохранение; введённые значения остаются в редакторе.

Пример: **Зарядка · 09:00 · Пн, Ср, Пт · Всегда по местному времени**.

## Изменение и удаление

У повторения календарь предлагает «Только это событие» и «Всю серию». Отдельное изменение не создаёт новую серию: для исходной даты записывается исключение, а изменённое событие сохраняется отдельно с привязкой к родительской серии. Вставка изменения и запись исключения проходят в одной транзакции.

Удаление одного повторения записывает исключение по его исходной дате. Остальные повторения продолжают рассчитываться. Удаление всей серии также удаляет её отдельные изменения. Квитанции уже выполненных команд сохраняются, поэтому повтор сохранения прежнего черновика не создаёт дубль.

Правка серии сохраняет ранее удалённые и отдельно изменённые повторения. Отдельные изменения сохраняют собственные поля. Проверка `revision` отклоняет устаревшую правку. Сохранение названия/примечания/ценности без явной замены расписания сохраняет исходное местное время и правило.

## Хранение и совместимость

`CalendarSchedule` содержит явный режим `FIXED`/`FLOATING`, локальные начало/окончание, правило и исключения. У `FLOATING` нет сохранённого часового пояса. `CalendarScheduleInput` отдельно хранит необработанные значения редактора, включая незавершённый ввод.

Room переведён с версии 3 на 4 добавочной миграцией. Добавлены nullable-поля `scheduleData`, `parentSeriesId` и индекс родительской серии. Старые события, идентификаторы, значения, примечания, версии и квитанции остаются на месте. При `scheduleData = NULL` используется прежняя логика UTC-события. Удаление/пересоздание базы не применяется.

Расписание кодируется версионированной строкой. Для floating источником истины служат локальные поля расписания; обязательные числовые поля старой таблицы остаются совместимым представлением, а проекция в конкретный пояс вычисляется при чтении. Нельзя трактовать эти числовые поля floating-записи отдельно от `scheduleData`.

Серия хранится одной записью. Повторения рассчитываются для запрошенного периода и получают стабильный ID вида `seriesId@YYYY-MM-DD`. Поиск и суммы за период используют те же рассчитанные повторения. Названия, ценности и примечания наследуются от серии.

Запрос без ограниченного периода возвращает определения серий и сохранённые отдельные события, а не бесконечный список повторений. Для разворачивания диапазона действует явный предел 366000 дней; превышение возвращает ошибку, без скрытого усечения результата.

В результатах поиска определение помечается «Серия» и «начало расписания» с указанием правила. Так начальный день, не входящий в выбранные дни недели/даты, не выглядит найденным повторением. Для floating выводятся исходное местное время и номинальная длительность.

Необязательные настройки черновика сохраняются в существующем DataStore. Старые черновики получают прежние значения по умолчанию: фиксированное время, без повторения. После начала сохранения настройки замораживаются вместе с остальными полями; повтор использует тот же requestId.

Контракт JSON локальной модели не расширен. Режим времени и повторения задаются пользователем в редакторах.

## Календарные границы

Интервалы считаются по календарным датам. Каждые N недель означает тот же день через N × 7 календарных дней. Ежемесячный повтор сохраняет число месяца; отсутствующие числа пропускаются, например 31 января → 31 марта.

Для floating окончание и длительность выражаются в местном времени. Для фиксированной серии сохраняется фактическая длительность исходного события. При переводе часов несуществующее время начала сгенерированного повторения пропускается; при двойном времени используется первое вхождение, без дублирования даты.

Floating time соответствует смыслу [RFC 5545, §3.3.5](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.3.5). Пропуск несуществующих повторений описан в [§3.3.10](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.3.10). Это реализация выбранных правил приложения, а не импортёр/экспортёр полного формата iCalendar.

Изменение относится к календарным событиям и их отображению. Системный планировщик напоминаний в этот объём не входит.
