# Автоматический выбор Vulkan, OpenCL и CPU на Android

20 ноября 2026 года в обычную сборку приложения подключён OpenCL для локальной генерации GGUF. Календарь, чат и выжимки используют один порядок выбора вычислителя. Модель остаётся на устройстве. [Измерения и состав APK](validation/LLM_OPENCL_AUTO_2026_11_20.json)

## Что видит пользователь

**Настройки → Вычисления AI** позволяет выбрать «Авто» или «CPU» для профиля «Календарь» либо «Чат и выжимки». После загрузки и генерации здесь видны фактический API, устройство, число слоёв на GPU, причина выбора, время подготовки, время до первого токена и скорость. Например, полная выгрузка на Redmi отображается как **GPU · OpenCL, 29 из 29**. При частичной выгрузке подпись меняется на **GPU + CPU · OpenCL**. Сведения относятся к текущему запуску движка. [Экран настроек](../app/src/main/java/com/example/aiassistent1/presentation/ui/InferenceSettingsControls.kt)

- **Авто** сначала проверяет Vulkan, затем OpenCL, затем CPU. Движок выбирает первый GPU, который принимает модель, располагает памятью и проходит пробное вычисление. Тот же порядок действует для небольших моделей, даже если замер показывает более быстрый CPU. Если полная выгрузка не помещается, движок проверяет меньшие количества слоёв.
- **CPU** сразу использует процессор. Выбор сохраняется отдельно для каждого профиля. [Параметры генерации](../app/src/main/java/com/example/aiassistent1/domain/model/GenerationParams.kt) · [Порядок выбора](../app/src/main/java/com/example/aiassistent1/data/engine/LlamatikEngine.kt)

## Загрузка и восстановление

1. Рабочий процесс `:llm` открывает плагин и выбирает устройство из его реестра GGML. Kotlin получает название API, устройство и подтверждённое число выгруженных слоёв через JNI и Binder. При первой загрузке сочетания модели, драйвера, API и числа слоёв выполняются обработка короткого входа и декодирование. [Нативный движок](../app/src/main/cpp/automatic_llama_jni.cpp) · [Рабочий процесс](../app/src/main/java/com/example/aiassistent1/data/engine/LlamaWorkerService.kt)
2. Расчёт памяти учитывает резерв Android, бюджет устройства, контекст, batch, размер выходного слоя и последних блоков GGUF. Для OpenCL дополнительно учитывается предел одного выделения драйвера. При нулевом доступном бюджете движок пропускает GPU. [Расчёт памяти](../app/src/main/java/com/example/aiassistent1/domain/model/ModelMemory.kt) · [Свойства драйвера](../app/src/main/cpp/gpu/opencl/driver_info.cpp)
3. При отказе до первого фрагмента приложение пробует следующий вычислитель. После сбоя GPU во время видимого вывода оно очищает незаконченный ответ и повторяет тот же запрос один раз на CPU. Отмена пользователем останавливает цепочку. При потере рабочего процесса следующая попытка получает новый процесс. Постоянный кеш ограничен явными ошибками совместимости и привязан к версии приложения, прошивке, драйверу, API и файлу модели. [Связь с рабочим процессом](../app/src/main/java/com/example/aiassistent1/data/engine/RemoteLlamaRuntime.kt)

## Что измерено

Физический **Redmi Note 11E Pro**, Android 13, Adreno 619. Драйвер Vulkan сообщает **1.1.128**, закреплённому Vulkan-плагину требуется **1.2**. Для обеих моделей режим «Авто» выбрал OpenCL. На каждую модель прошли календарный запрос, чат и краткая выжимка. В календарном ответе штатный парсер получил команду `calendar_add` и название «Встреча». В этом испытании записи в пользовательском календаре не создавались. [Android-тест](../app/src/androidTest/java/com/example/aiassistent1/data/engine/GpuAutomaticInstrumentedTest.kt)

| Модель V12.67 Qwen3-0.6B | Слоёв на GPU | Подготовка OpenCL при первом календарном запросе | Декодирование OpenCL | Декодирование при явном CPU |
| --- | ---: | ---: | ---: | ---: |
| Q8_0 | 29 из 29 | 44,9 с | 3,30 токена/с | 9,06 токена/с |
| Q4_K_M | 29 из 29 | 58,1 с | 4,12 токена/с | 8,13 токена/с |

В таблице приведено первое выполнение одного календарного запроса каждым способом в release-сборке. Q8_0 выдала 30 токенов, Q4_K_M — 31 для каждого вычислителя. Время подготовки и скорость декодирования записаны раздельно. В release и обычной debug-сборке пройдены все три задачи. Диагностическая сборка ранее подтвердила завершение матричных ядер на очереди Adreno при обработке входа и генерации, с 1 и с 29 слоями для обеих моделей. [Испытания нативных ядер](LLM_OPENCL_ANDROID_PROBE.md)

- На Q8_0 тест завершил собственный процесс модели после первого фрагмента ответа OpenCL. Состоялся один перезапуск на CPU, один вызов готовности и получен полный календарный JSON.
- При скрытом системном драйвере OpenCL на Redmi режим «Авто» выбрал CPU для всех трёх задач. На эмуляторе Android 15 x86_64 со страницами **16 КиБ** Q4_K_M выполнила все три задачи через CPU в обычных debug и release.
- В двух инструментальных тестах Compose проверены отдельный пункт настроек, выбор CPU, полная и частичная выгрузка OpenCL и подпись Vulkan. В модульных тестах приложения прошли **857 из 858**. Один отчётный тест требует внешний набор `CALENDAR_PROMPT_EVALUATION` и пропущен по своему условию. [Тесты настроек](../app/src/androidTest/java/com/example/aiassistent1/presentation/ui/InferenceSettingsInstrumentedTest.kt) · [Тесты переключения](../app/src/test/java/com/example/aiassistent1/data/engine/AutomaticComputeTest.kt)
- Дополнительно прошли 22 теста календарного ядра и 20 тестов Android-хранилища. Для установки на телефон и эмулятор временную копию release подписали локальным тестовым сертификатом Android. Универсальный `app-release-unsigned.apk` подготовлен для подписи ключом выпуска.

## Поставка и совместимость

Универсальные debug и release APK содержат Vulkan для `arm64-v8a`, `armeabi-v7a`, `x86` и `x86_64`. OpenCL в этой сборке включён для **arm64 с совместимым драйвером Adreno**. Только `libggml-opencl.so` импортирует системную `libOpenCL.so`. В манифесте драйвер объявлен необязательным. В обоих APK проверены 41 библиотека для 64-битных ABI и выравнивание их ELF-сегментов и записей ZIP на 16 КиБ. Трассировка ядер и диагностический сервис подключаются отдельным флагом debug-сборки. [Конфигурация](../app/src/main/cpp/gpu/opencl/CMakeLists.txt) · [Манифест](../app/src/main/opencl/AndroidManifest.xml) · [Правила Android](https://developer.android.com/guide/topics/manifest/uses-native-library-element)

Для нового пути OpenCL в APK вложены MIT для GGML и YaRN, Apache-2.0 для компонентов Khronos и ведомость компонентов. Дополнительно сохранён MIT из тега Llamatik 1.10.1. POM опубликованного Android-артефакта той же версии указывает Apache-2.0. При проверке AAR и его `classes.jar` отдельных файлов LICENSE или NOTICE внутри этих архивов не обнаружено. Ведомость указывает происхождение обоих текстов. Драйвер поставляется прошивкой телефона. Условия распространения весов рассматриваются отдельно в исходном плане. [Ведомость в APK](../app/src/main/assets/licenses/OpenCL-NOTICE.txt) · [Лицензии компонентов и базовой модели](LLM_OPENCL_ANDROID_PLAN.md)

Приложение поддерживает установку начиная с Android 11 (API 30). Физическая проверка в этой серии охватила Adreno 619. Испытания на конкретных Mali, Xclipse, других Adreno, на телефоне с рабочим Vulkan 1.2+ и на физическом Android-устройстве со страницами 16 КиБ остаются открытыми.

## Повторить проверку

В обычной debug-сборке режим «Авто» доступен сразу. Для повторения теста с одним подключённым телефоном и установленной в приложении моделью Q8_0 используются следующие команды PowerShell.

```powershell
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest
adb install -r -t app/build/outputs/apk/debug/app-debug.apk
adb install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
$test = 'com.example.aiassistent1.data.engine.GpuAutomaticInstrumentedTest'
$runner = 'com.example.aiassistent1.test/androidx.test.runner.AndroidJUnitRunner'
$model = 'calendar-assistant-v12.67-Qwen3-0.6B-Q8_0.gguf'
adb shell am instrument -w -e class $test -e gpuModel $model $runner
```

Аргумент `-e expectedAuto OPENCL` проверяет ожидаемый способ на известном устройстве. На тестовом телефоне аргумент `-e exerciseGpuFailure true` дополнительно завершает собственный процесс генерации после первого фрагмента и проверяет восстановление. AndroidJUnitRunner возвращает измерения в поле `gpuReport`. Контрольный debug APK без объявления драйвера собирается с `-PassistantOpenClProbeHideDriver=true`.
