# Автоматический контекст и память модели

Изменение от 4 октября 2026 года.

## Поведение

- Вход измеряется токенизатором выбранного GGUF после сборки полного ChatML-запроса: системная инструкция, выбранная история, текущий запрос и служебные маркеры.
- В чате начальный резерв ответа — 512 токенов. При входе 513–1024 он составляет 1024, при 1025–1536 — 1536 и далее с шагом 512. Начальный контекст равен четырём резервам, с ограничением по метаданным GGUF и оценке RAM.
- Резерв не ограничивает длину ответа. При полном входе 100 и контексте 2048 доступно 1932 выходных токена: 16 оставлены для технического запаса. Ответ в 1200 токенов не останавливается на 512.
- При заполнении контекста движок пробует расширение. Сохраняются точные идентификаторы входа и уже созданного ответа, состояние семплера, ещё не выведенные байты UTF-8 и уже выбранный следующий токен. KV-контекст пересоздаётся и заполняется этими же токенами; ранее показанный текст повторно не выводится.
- Когда расширение невозможно, поток заканчивается явной ошибкой. `ChatResponseWriter` сохраняет ответ как прерванный. Календарная команда выполняется только после успешного окончания потока и разбора полного JSON.
- Короткий следующий запрос сохраняет рабочую конфигурацию. Новая оценка свободной RAM не выгружает уже работающую модель. При переключении календаря, чата и выжимки учитываются их отдельные потребности. При нехватке памяти может использоваться уже выделенный подходящий контекст.
- Batch подбирается автоматически: 64 для календаря и короткого входа, 128/256/512 для более длинного. Перед новой аллокацией проверяются меньшие пакеты. Неудачная аллокация контекста получает одну попытку с минимальным подходящим контекстом и batch 64.

## Длинные тексты

Выжимка конференции читает исходник страницами. Каждый фрагмент вместе с инструкцией проверяется токенизатором. Промежуточные результаты объединяются деревом; исходные фрагменты и завершённые ответы не обрезаются по байтам. Если модель не может достаточно сократить текст за три попытки, возвращается ошибка, а исходная запись сохраняется.

В обычном чате при переполнении сначала исключаются ответы ассистента из передаваемой истории. Если запросы всё равно не помещаются, строится явно обозначенная выжимка длинного текста. Сообщения в базе и интерфейсе сохраняются. Календарные запросы не подменяются выжимкой.

Поле обычного чата принимает до 100 000 символов вместо прежних 3 000. Этот предел защищает интерфейс и хранение, а не заменяет измерение токенов. Вставка не обрезается: при превышении предела текст остаётся в поле, отправка отключается и показывается причина. Лимиты календарного запроса и голосового черновика остаются 3 000 символов.

## Реализация

`AutomaticContextPolicy` отделяет начальный резерв от доступного выхода. `LlamatikEngine` сериализует запросы, фиксирует параметры на время генерации и различает EOS, отмену и заполнение контекста. Ошибка передаётся после уже выданных фрагментов, чтобы не потерять хвост ответа в буфере потока.

`AutomaticLlamaBridge` использует публичный C API существующей `libllama.so` из Llamatik 1.10.1. Дополнительная копия весов или llama.cpp не упаковывается. Заголовки ABI закреплены в `app/src/main/cpp/third_party/llama_api/README.md`; обновление библиотеки требует повторной проверки ABI. Модель загружается с mmap. Текст проходит JNI как байты UTF-8, а не Modified UTF-8.

Нативные операции выполняются на одном выделенном Java-потоке; вычислительные потоки llama.cpp задаются отдельно. Это позволяет повторно использовать одну команду нативных рабочих потоков между запросами.

В настройках вместо ручных размеров контекста, ответа, batch и выбора соотношения показаны фактические размеры последнего запроса. Сэмплирование и настройка потоков CPU сохранены. Живая оценка RAM не обнуляет сохранённые параметры.

Обучающие данные, веса моделей, системные правила и календарный контракт не изменялись.

## Ограничения

Контекст конечен. Расширение зависит от физической RAM и предела GGUF; Android может завершить процесс при критической нехватке памяти. Код не обещает резервирование RAM против операционной системы. Качество и полнота смысловой выжимки зависят от модели; прохождение всех фрагментов через токенизатор само по себе не доказывает сохранность каждого факта.

### Обнаруженная ошибка качества модели

На запрос «Создай встречу Проверка памяти завтра в двенадцать пятнадцать на тридцать минут» оба движка — прежний Llamatik JNI и новый мост — вернули одинаковый текст при одинаковом фиксированном системном сообщении и параметрах выборки. Параметры верные: `starts_at=2026-10-05T12:15`, `duration_min=30`. В `reply` получено ошибочное «в двенадцать минут первого». В этом сравнении ошибка воспроизводится и до изменения управления памятью. Обучение и исправление формулировки не выполнялись; успешный разбор параметров не считается подтверждением правильности `reply`.
