# V12.53: часы с минутами и озвучивание без части суток

Версия набора: **V12.53**. Основа: V12.52. Подготовлены данные для обучения;
веса модели этой подготовкой не изменяются.

## Понимание времени и текст ответа

Модель учитывает «утра», «дня», «вечера» и «ночи» во входном запросе,
чтобы определить точное время. При произнесении времени в `reply`
эти уточнения опускаются.

| Входное выражение | Точное время в параметрах | Форма в reply |
| --- | --- | --- |
| четверть третьего дня | 14:15 | в четверть третьего |
| четверть третьего ночи | 02:15 | в четверть третьего |
| полтретьего дня | 14:30 | в полтретьего |
| половина третьего ночи | 02:30 | в половине третьего |
| без четверти семь вечера | 18:45 | без четверти семь |
| пять минут третьего дня | 14:05 | в пять минут третьего |
| десять часов утра | 10:00 | в десять часов |
| двадцать три пятьдесят пять | 23:55 | в пятьдесят пять минут двенадцатого |

Это правило действует для всех форм времени, включая начало и окончание
события. В `reply` сохраняются точные минуты: нельзя превращать двадцать
минут в четверть часа или округлять пятьдесят пять минут до целого часа.
Одинаковая краткая фраза ответа может соответствовать двум половинам суток;
точное значение уже хранится в `params`. Из ответа его повторно не извлекают.

**Правила оформления относятся только к `reply`.** Они не преобразуют
`params`, названия событий, поисковые запросы, входной текст, system-контекст,
даты, длительности или значения. «Через три дня», «за два дня» и название
«Сверка плана следующего дня» сохраняются. Отдельное слово «дня» не служит
основанием для удаления текста.

## Короткая запись текущего часа

В конструкции «час пять» указан текущий час и число минут после него.
В конструкции «пять минут первого» назван следующий час.

| Запрос о времени | Часы и минуты |
| --- | --- |
| час пять / один час пять минут | 01:05 |
| час десять | 01:10 |
| час пятнадцать | 01:15 |
| два двадцать пять | 02:25 |
| двенадцать тридцать | 12:30 |
| двадцать пять | 20:05 |
| двадцать один двадцать пять | 21:25 |
| двадцать два сорок | 22:40 |
| двадцать три пятьдесят пять | 23:55 |
| ноль пять | 00:05 |
| ноль часов | 00:00 |
| пять минут первого ночи | 00:05 |

Для часов 00–23 представлены минуты 05–55 с шагом пять. Составные часы
«двадцать один», «двадцать два» и «двадцать три» читаются целиком.
Из текущего часа не вычитают единицу и не прибавляют двенадцать часов.
Старые формы «час ноль ноль» и «ноль часов ноль ноль минут» сохраняются.

«Завтра в ноль часов» означает начало завтрашней даты. «Завтра в двадцать
три пятьдесят пять» остаётся завтрашней датой. Упоминание следующего
названного часа в ответе не переносит дату ещё на сутки.

В «в двадцать пять на десять минут» время равно `20:05`,
а `duration_min` равно `10`. Длительности после «на», смещения после
«через» и прежние правила даты сохраняют свой смысл.

## Ручные материалы

[338 полных новых примеров](calendar_assistant_v12_53_compact_clock_manual.json)
содержат отдельно написанные system, user и полный assistant JSON.
Предложения, перестановки и ответы не создаются генератором шаблонов.

| Выборка | Основная сетка | Дополнение для полуночи | Всего новых |
| --- | ---: | ---: | ---: |
| Train | 24 часа × 11 минут = 264 | 1 | 265 |
| Validation | 24 часа × 3 минуты = 72 | 1 | 73 |

Train использует краткие часы с минутами, validation — полные формы с
«час/часа/часов» и «минут». События и system-контекст отличаются.
Train проверяет переход на первое число месяца, validation — на новый год.
В основной сетке каждый из шести порядков события, дня и времени встречается
44 раза в train и 12 раз в validation. Эти квоты относятся к новому слою,
а не ко всем категориям накопленного набора.

[Ручной реестр исправлений reply](calendar_assistant_v12_53_reply_edits_manual.json)
содержит полные новые тексты для наследуемых ответов. Заменяются только
`assistant.reply`: 260 train, 74 validation и три regression holdout.
Часть суток остаётся во входных запросах и учитывается в точном времени.
Исходные файлы V12.52 сохранены; остальные поля их копий не меняются.
В двух других holdout сохраняются все байты, в regression holdout —
все запросы, параметры, разбиение и порядок записей.

Итог: **2401 train, 720 validation, 36 + 8 + 63 holdout**.
Сохраняются шесть календарных intents V12.4. У новых записей остаётся
JSON-контракт `v12.5`; номер набора и версия контракта — разные значения.

`prepare_v12_53.py` проверяет готовые строки, копирует буквальные
исправления и сериализует JSONL. Он не генерирует текст, не исправляет
его эвристически и не запускает обучение.

## Приложение и проверка

`CalendarReplyTimeFormatter` формирует начало и окончание события без
части суток. Название копируется отдельно, исходное время остаётся
`LocalDateTime`; форматирование не меняет параметры события.
Промпт модели, парсер и операции календаря в этом дополнении не изменялись.

Пройдены 136 Python-тестов, включая прежние наборы, и 10 тестов
Android-форматтера. Проверены все 1440 сочетаний часа и минуты для отсутствия
добавленной части суток; отдельные проверки сопоставляют точные фразы,
переходы через полночь и сохранение названий.

Все 3228 записей прошли токенизацию без обрезания с прежним chat template
и лимитом 256 токенов. Максимум новых train-примеров — 174 токена,
новых validation-примеров — 180. Веса модели для этой проверки не загружались.

Результаты проверок сохранены в
[validation_report.json](calendar_sft_v12_53/validation_report.json) и
[tokenization_report.json](calendar_sft_v12_53/tokenization_report.json).
Они подтверждают подготовку данных и проверенные ветви форматтера.
Обучение, оценка ответов модели, сборка GGUF и проверка на телефоне
в рамках этой подготовки не запускались.
