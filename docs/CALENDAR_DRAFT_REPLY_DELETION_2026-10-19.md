# Совместное удаление черновика и связанного ответа

## Поведение

Удаление через редактор черновика убирает карточку и связанный ответ. Запрос пользователя, остальные сообщения, другие черновики и события календаря сохраняются. Итоговое отображение уточнено позднее в тот же день: сначала виден ответ модели, затем он плавно сменяется карточкой без отдельного `reply` над ней. Сам текст остаётся в истории для автоматического озвучивания до удаления. См. [появление карточки](CALENDAR_DRAFT_APPEARANCE_2026-10-19.md).

Ответ и карточка связаны существующим `requestId == message.id`. Отдельные кнопки удаления сообщения и повторной генерации у этой пары скрыты, чтобы не оставлять черновик без связанного сообщения. Сохранённый черновик, выполняющееся сохранение и запрос с `saveRequested` по-прежнему нельзя удалить.

## Почему удаление устойчиво

- `CalendarDraftController` сначала сохраняет запись с `discardRequested = true`, затем удаляет ответ из Room и только после этого убирает отметку из DataStore. После перезапуска незавершённое удаление повторяется безопасно.
- Room удаляет только запись с нужным ID, `chatId = calendar` и ролью `ASSISTANT`. Запрос пользователя защищён и в базе, и при фильтрации интерфейса.
- Удалённые ответы скрываются из текущего списка и из запоздавших снимков Room. Позднее обновление сообщения или форматирование поля не возвращает удалённую пару.
- При ошибке остаётся сообщение об ошибке и существующая кнопка «Повторить сохранение черновиков». Подтверждение удаления поясняет: «Черновик и связанный ответ ассистента будут удалены из чата. Ваш запрос останется.»
- Старые записи DataStore без нового поля читаются как обычные черновики. Схема Room, данные события, правила парсинга и автоматическое озвучивание не меняются.

## Проверки первоначальной реализации удаления

Добавлены сценарии защиты остальных черновиков, недопустимого удаления, ошибок записи и удаления ответа, повторных нажатий, перезапуска между операциями, запоздавшей истории и чтения старого формата DataStore. В этом запуске UI-тест проверял совместный показ, текстовые действия и переход к сохранённому событию; позднее проверка обновлена под окончательное поведение. Отдельный Android-тест проверяет выборочное удаление ответа и повторное открытие изолированной базы Room.

`./gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest --offline --console=plain` завершился успешно: 684 JVM-теста, 0 ошибок, 1 пропуск. Пропущен существующий тест `CalendarPromptContractTest`, которому нужен каталог внешней оценки модели (`CALENDAR_PROMPT_EVALUATION`). Собраны APK приложения и Android-тестов.

Первый запуск выявил ошибку переименования временного файла DataStore в Windows при повторной записи нового теста старого формата. Подготовка теста изменена на однократную запись исходного JSON без нового поля; повторный полный запуск успешен. Рабочая реализация DataStore из-за этой ошибки не менялась.

На отдельном временном эмуляторе Android 15 / API 35 / x86_64 / 16 KB прошли все 9 инструментальных тестов: `CalendarReplyCardTest` (4), `CalendarDraftCardsTest` (4), `CalendarDraftReplyStorageTest` (1). Проверены видимость ответа и карточки, копирование и передача текста в озвучивание, открытие редактора и сохранённого события, независимость черновиков, повторные записи DataStore и выборочное удаление ответа с повторным открытием Room. Журнал: `app/build/reports/androidTests/draftReply20261019/emulator-run.txt`.

Проверки выполнялись прямым `adb shell am instrument` с явным указанием временного эмулятора. Физический телефон не подключался; генерация локальной моделью и фактическое звучание TTS на телефоне не проверялись.
