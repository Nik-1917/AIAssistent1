# Резерв профиля 007 при запуске и выходе из гибернации

12 октября 2026 года пользователь подтвердил замену почасового обновления на однократное обновление после включения, перезагрузки или выхода из гибернации. Перед переходом в гибернацию копия не создаётся.

## Поведение

- Windows запускает задание через 2 минуты после старта системы (`BootTrigger`) либо зарегистрированного выхода из гибернации (`Microsoft-Windows-Power-Troubleshooter`, событие 1, `EffectiveState=5`).
- Почасовой интервал, повторения и запуск при входе пользователя удалены. Задание не будит компьютер для копирования.
- Идентификатор текущего старта/пробуждения записывается до запуска резервирования. Повторный сигнал того же события пропускается, включая случай ошибки первой попытки. Следующая автоматическая попытка будет при следующем старте/пробуждении.
- Работы выполняются последовательно. Если предыдущее обновление ещё выполняется, новое событие ставится в очередь; дополнительная блокировка исключает параллельный запуск служебной оболочки.
- Успешный резерв, уже выполненный после текущего пробуждения, учитывается при установке: проверка нового задания не создаёт повторный снимок.

Сжатие Restic, источник `C:\Users\007`, архив `D:\Backups\007-restic`, проверка новых данных и режим `LatestOnly` сохраняются. Удаления и изменения на C: отражаются в архиве после ближайшего успешного обновления и очистки. Файлы, созданные или изменённые между такими запусками, попадут в архив при следующем успешном обновлении.

Меняется расписание и добавляется защищённая оболочка `C:\ProgramData\ProfileBackup007\startup-backup.ps1`. Рабочие файлы резервирования и очистки не меняются. Внутреннее имя задания `ProfileBackup007-Hourly` и аргумент рабочего скрипта `-Mode Hourly` сохранены для совместимости; периодичность определяется новыми триггерами Windows.

## Проверки

Тест в Windows PowerShell 5.1 прошёл: различение старта и пробуждения, пропуск прежнего события, пропуск дубля, один запуск при новом пробуждении, блокировка параллельной работы, отсутствие автоматического повтора ошибки и отсутствие почасовых триггеров. Фильтр задания совпал с тремя реальными событиями выхода из гибернации в журнале компьютера. Тестовая функция вместо Restic меняла счётчик в отдельной папке; рабочий архив не затрагивался.

Отдельная проверка выполнила точный блок запуска дочернего процесса из оболочки с тестовым рабочим скриптом: реальный Windows PowerShell 5.1 запустился, новое успешное состояние принято, прежнее успешное состояние отклонено, ненулевой код дочернего процесса передан. По состоянию на 13:13 по Самаре прежний часовой момент 13:11 прошёл без нового резервирования; последний успешный снимок и состояние резерва сохранились.

Изменение применено 12 октября 2026 года в 13:09 по Самаре. Экспорт зарегистрированного задания содержит ровно два триггера с задержкой `PT2M`, без `TimeTrigger` и `Repetition`; задание включено, выполняется от SYSTEM, политика параллельных экземпляров — `Queue`. Реальный проверочный запуск задания завершил оболочку со статусом `SKIPPED_ALREADY_ATTEMPTED`, кодом 0: успешный резерв текущего пробуждения уже существовал. Контрольные суммы исходного рабочего скрипта, очистки и сбора метаданных совпали с прежними значениями. Фактическая перезагрузка/гибернация для испытания не выполнялась.

До установки проверка исходного задания была исправлена: PowerShell возвращает локализованное имя учётной записи `СИСТЕМА`, экспорт XML — постоянный SID `S-1-5-18`. Сверка использует SID из XML, учитывает значение `Enabled=true` по умолчанию и сравнивает длительность интервала как `TimeSpan`. Первая остановка произошла до изменения исходных настроек.

Результаты сохранены в `docs/profile_backup_007_2026_10_12_startup_result.json` и `C:\ProgramData\ProfileBackup007\schedule-upgrade.json`. Предыдущие конфигурация и XML задания сохранены в защищённой папке `C:\ProgramData\ProfileBackup007\schedule-upgrade-2aad98544a974e7fa4c489e3e02727c4`.
