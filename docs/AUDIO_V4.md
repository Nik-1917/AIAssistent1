# Аудиосистема v4: реализация и проверка

Состояние на 23 сентября 2026 года. Это описание текущей реализации, а не подтверждение всех целевых требований на любых Android-устройствах.

## Реализовано

- Потоковое кодирование PCM 16 кГц, mono в настоящий MP3 через LAME/JNI. Запись ограничена тремя часами, работает через microphone Foreground Service и WakeLock. Файл сохраняется во внутренней папке или в выбранной пользователем папке через SAF, включая доступную SD-карту.
- Раздельные обработчики захвата и распознавания с ограниченной очередью. Если распознавание не успевает, запись продолжается, а неполный транскрипт явно помечается. Продолжительность считается по аудиосэмплам.
- Нативные WebRTC NS/AEC с кадрами 10 мс и передачей воспроизводимого TTS в опорный канал AEC. При недоступности нативной библиотеки используются доступные эффекты Android. Для конференций обработка отключаема.
- Активация по имени, звуковой сигнал, вибрация перед ответом и видимый статус. Поддерживается пользовательский звуковой файл.
- Voice ID: локальный отпечаток вне Android backup; новое обучение при включении функции и смене имени; проверка ревизии защищает от сохранения результата старого обучения. Повреждённый или отсутствующий отпечаток не разрешает выполнение чужой команды. Изменение автосводки не сбрасывает Voice ID.
- Barge-in останавливает используемый чатом контроллер генерации/озвучивания. При включённом Voice ID прерывание происходит после проверки сегмента речи; это увеличивает задержку относительно обычного VAD.
- Room v3: отдельные строки транскрипта, временные метки, Paging 3, FTS4 с поиском по префиксам слов, миграции v1/v2 без разрушения конференций. Лимиты текста: 5 MiB на конференцию и 100 MiB суммарно; очистка старого текста сохраняет аудиофайлы.
- Экран записей: поиск, воспроизведение и переход по фразе, экспорт MP3, подтверждение удаления, создание выжимки. Детали и развёрнутая выжимка прокручиваются вместе с транскриптом.
- Сводка использует существующий LLM-движок, постранично читает Room и обрабатывает ограниченные порции текста. Для неё применяется контекст 4096 и ограничение ответа 512 токенов. Движок закрывается после сводки; следующий запрос чата загружает его с параметрами чата.
- Дополнительная защита завершения: отменённое ожидание микрофона не оставляет владельца; тайм-аут занятости отображается как ошибка; ошибки остановки отдельных ресурсов не препятствуют освобождению микрофона и обновлению состояния UI; ошибка запуска службы записи отображается пользователю.

## Отличия от целевого плана и непроверенные свойства

В комплекте **нет совместимой русской KWS-модели**. Сейчас имя определяется локальным ASR, что указано в настройках. GigaAM из приложения является offline ASR и не подставляется в online KWS. Реальный Sherpa KWS включается только при наличии совместимого пакета Zipformer2 в `app/src/main/assets/voice/kws/`: `encoder.onnx`, `decoder.onnx`, `joiner.onnx`, `tokens.txt`. Одного переименования ASR-файлов недостаточно. Скорость и точность настоящего русского KWS пока не подтверждены.

WebRTC здесь — исходники отдельных классических C-компонентов AEC/NS, **не полный современный WebRTC APM/AEC3**. Аппаратный ANC наушников приложение не реализует. Эффективность эхоподавления на разных маршрутах аудио, Bluetooth, дальнем микрофоне и при высокой громкости требует отдельного измерения на устройствах.

Проверка совпадения голоса не является проверкой личности или защитой от воспроизведения записи. Метрики ложного допуска/отказа, обучение по очень короткому имени и работа модели с разными русскоязычными голосами не измерены. Первое корректное обращение после сброса становится новым эталоном согласно пользовательскому плану.

Пользователь сообщил об успешной проверке приложения на телефоне. Полный трёхчасовой сеанс реального микрофона с выключенным экраном, энергопотребление, динамическая смена аудиомаршрута и качество LLM-выжимок в этом цикле инструментально не проверялись. Ускоренный тест кодирования не заменяет эти проверки.

## Воспроизводимость ресурсов

ONNX/AAR/WAV и TTS-ресурсы исключены из Git существующим `.gitignore`. Базовые ASR/VAD/TTS и Sherpa runtime подготавливаются согласно [VOICE_RUNTIME.md](VOICE_RUNTIME.md).

Дополнительная модель Voice ID находится локально в `app/src/main/assets/voice/speaker/model.onnx`. Чтобы восстановить её после клонирования:

```powershell
./tools/fetch-audio-assets.ps1
# Только проверить уже существующий файл, без сети:
./tools/fetch-audio-assets.ps1 -VerifyOnly
```

Скрипт загружает в отдельный временный файл, проверяет SHA-256 и только затем перемещает файл на место. Существующий файл с другим хэшем не перезаписывается.

- Источник: [Sherpa ONNX speaker model release](https://github.com/k2-fsa/sherpa-onnx/releases/download/speaker-recongition-models/3dspeaker_speech_campplus_sv_en_voxceleb_16k.onnx).
- SHA-256: `357a834f702b80161e5b981182c038e18553c1f2ca752ed6cec2052365d4129b`.
- Файл: CAMPPlus, `3dspeaker_speech_campplus_sv_en_voxceleb_16k.onnx` (29 596 978 байт). Лицензия конкретных весов отдельно не верифицирована; ссылка и хэш фиксируют происхождение, а не разрешение на распространение.
- `assets/sounds/activation.mp3` — синтезированный короткий сигнал, а не сторонняя музыкальная запись.

Нативные исходники включены в репозиторий:

| Компонент | Источник и ревизия | Путь и уведомления |
| --- | --- | --- |
| LAME 3.100 | `https://github.com/ffmpegwasm/lame`, `2badea1974ae36cb8312afe99cff1e6b3b5decee` | `app/src/main/cpp/third_party/lame`, `COPYING` |
| Классические WebRTC AEC/NS | `https://github.com/hwt77/webrtc-android-jni`, `9f2d5f3d79098a17e85b0d09779a79f600c0896d` | `app/src/main/cpp/third_party/webrtc`; заголовки исходников, `LICENSE`, `PATENTS`, `AUTHORS` |

Файлы `LICENSE`, `PATENTS`, `AUTHORS` для WebRTC дополнительно получены из `webrtc-mirror/webrtc` (ветка main на момент загрузки); это не отдельная проверка исторических условий каждого файла зеркала. CMake собирает `libmp3lame.so` и `libassistant_audio.so` для четырёх ABI. Конфигурация: NDK `28.2.13676358`, CMake `3.22.1`.

## Выполненные проверки

До заключительных правок завершения записи: 267 unit-тестов, 0 ошибок (`build/audio-validation.log` и XML unit-результатов). Нативные библиотеки собраны для четырёх ABI; debug APK собран.

Последний полный инструментальный аудиопрогон: **7 тестов, 0 ошибок, 0 пропусков**, Android 15 / API 35, x86_64, эмулятор с размером страницы 16 KiB. Результат: `build/audio-final-instrumentation.log` и `app/build/outputs/androidTest-results/connected/debug/`.

| Проверка | Что подтверждено |
| --- | --- |
| `AudioNativeTest` (3) | MP3 читается Android MediaExtractor; 16 кГц/mono; сессии кодера независимы; WebRTC выдаёт конечные ограниченные значения и отклоняет кадр неверной длины; потоковое кодирование трёх часов PCM постоянным входным буфером |
| `ConferenceStorageTest` (2) | Миграция, сохранение данных, префиксный FTS-поиск, пагинация, реальный объём текстовых строк около 100 MiB, удаление текста без удаления аудио |
| `VoiceEnrollmentTest` (1) | Сброс эталона после смены имени, повторное обучение, отказ при некорректном embedding/повреждённом профиле |
| `AudioModelIntegrationTest` (1) | Синтез и распознавание тестовой фразы реальными комплектными моделями; извлечение speaker embedding и сравнение с ним самим |

Ускоренный прогон трёх часов тишины создаёт MP3 около 86.4 MB и проверяет длительность около 10 800 секунд. Он не измеряет память всего приложения с живым ASR и не длится три часа реального времени.

Заключительные изменения проверены отдельно: компиляция успешна, **4 unit-теста `MicrophoneCoordinatorTest` прошли без ошибок** (`build/audio-final-hardening.log`). Проверены передача владения, отмена ожидающего, тайм-аут занятости и сохранение отмены вызывающей корутины. Полный нагрузочный прогон ради этих правок повторно не запускался. Отрисовка обновлённой прокрутки на физическом устройстве отдельно не проверялась.

После заключительных правок `:app:assembleDebug --offline` завершился успешно (`build/audio-final-apk.log`). APK: `app/build/outputs/apk/debug/app-debug.apk`. Установка этого APK на пользовательский телефон в заключительном цикле не выполнялась.

```powershell
./gradlew.bat :app:compileDebugKotlin :app:testDebugUnitTest --tests com.example.aiassistent1.data.provider.MicrophoneCoordinatorTest --offline
```

Команда полного инструментального прогона приведена для воспроизведения, не для автоматического повторения на пользовательском телефоне:

```powershell
./gradlew.bat :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.package=com.example.aiassistent1.audio --offline
```
