# Две компактные календарные модели

Дата: 2026-10-03. Основание: пользователь выбрал Qwen3-1.7B и Qwen3.5-2B после предложения подготовить компактные варианты.

## Область работы

Обучить два независимых LoRA-адаптера на исходных официальных весах, затем сохранить отдельные GGUF Q4_K_M. Данные и контракт остаются V12.63. Существующий адаптер 4B не подходит к другим архитектурам. Правила, примеры, Android-код и предыдущие артефакты сохраняются.

1. Зафиксировать ревизии и хеши исходных моделей, лицензию, данные, инструменты и зависимости. Для Qwen3.5 использовать отдельное окружение, сохранив рабочее окружение V12.63.
2. Проверить токенизацию всех записей без усечения, маску обучения только ответа и прямой JSON без рассуждений. Проверить один шаг обучения и генерацию на доступной GTX 1080 Ti.
3. Обучить каждый адаптер с нуля на существующих 5 628 учебных записях. Использовать три эпохи, сохранение промежуточных адаптеров и выбор по заранее зафиксированному development-набору. Не использовать результаты итоговой проверки для выбора адаптера.
4. Слить выбранные адаптеры с их исходными моделями, проверить конвертацию и собрать отдельные Q4_K_M. Для Qwen3.5 календарный артефакт содержит языковую часть; визуальные входы в эту задачу не входят.
5. Сравнить сырые ответы обеих GGUF с V12.63 на одинаковых запросах: JSON, контракт, intent, параметры, даты/время и смысл reply. Ранее использованные контрольные запросы называть регрессионными, а не новым слепым набором. Отдельно проверить фактический ChatML приложения.
6. Передать готовые файлы в Download подключённого телефона через временное имя и проверку SHA-256/размера. Запуск внутри Android-приложения отмечать отдельно от передачи файла и проверки на компьютере.

## Проверяемые ограничения

Точный размер, скорость, расход памяти и качество новых обученных моделей неизвестны до измерения. Успешное обучение или сборка GGUF не доказывают корректность всех ответов. Ошибки включаются в итоговый отчёт. У Qwen3.5 отдельно проверяется совместимость архитектуры с имеющимися средствами обучения, конвертации и Llamatik.

Текущий `LlamatikEngine.buildPrompt` использует ChatML с переводом строки перед `im_end` и открытым префиксом assistant, без префикса рассуждений. Новый обучающий конвейер должен учитывать этот формат, не меняя текст правил или содержимое русских примеров. Различия транспорта сообщений документируются и проверяются отдельно.
