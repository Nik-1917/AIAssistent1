# Calendar assistant v7 results

Дата проверки: 2026-08-28.

## Решение

Адаптер v7 обучен одной полной эпохой и проверен на неизмененном holdout из 57
случаев. Результат лучше v6 по всем четырем итоговым метрикам. Главный пример
H001 исправлен: `шесть сорок` распознано как `06:40`.

Модель пока не готова к слиянию, GGUF-конвертации или включению в Android.
После ручного утверждения допустимых вариантов H003 и H017 и принятия
необязательного префикса для H050 семантически пройден 31 из 57 случаев.
Остались ошибки календарной арифметики, полноты query и target, неполных
команд и reply-контракта.

Токенизатор не менялся. Слияние весов, конвертация и изменение Android или CLI
не выполнялись.

## Исправления

По сравнению с v6 семантически исправлены девять случаев:

- H001: `шесть сорок` теперь правильно дает `06:40`.
- H011: двадцать минут больше не превращаются в 120 минут.
- H012: `семь тридцать` теперь правильно дает `07:30`.
- H026: запрос всех дел больше не получает выдуманный query.
- H033: новое название передано без смысловой ошибки, отличается только регистр.
- H036: завтра после 2026-08-30 правильно дает 2026-08-31.
- H047: частичный add без длительности больше не заявляет создание события.
- H054: сумма за сегодня начинается с текущего времени 14:30.
- H062: более ранние два часа дня правильно перенесены на завтра.

## Регрессии

По текущему reply-контракту три случая, проходивших в v6, регрессировали в v7:

- H018: query `рейс` заменен пустой строкой.
- H051: выдуман title `Задача`, а обязательная сегодняшняя дата потеряна.
- H057: при отсутствии периода выдуман диапазон за сегодня.

H050 исключён из регрессий решением от 29 августа 2026 года. Для полного
`calendar_add` префикс `Событие создано:` предпочтителен, но необязателен.

## Заключение

Ручной корпус v7 достиг основной цели 24-часового времени: H001, H012 и H062
исправлены. Он также улучшил старое ядро holdout на пять семантических случаев.
Високосная граница H004 не закреплена. После ручного утверждения H003 и H017 и
переклассификации H050 остаются три регрессии: H018 в query, H051 в неполном
add и H057 в команде без периода.

Адаптер следует сохранить как проверенный эксперимент v7. Продвигать его в
слияние, GGUF и Android нельзя. Следующий этап должен разбирать ошибки по одной,
начиная с регрессий и правил неполных команд, без повторного обучения до ручного
пересмотра данных.
