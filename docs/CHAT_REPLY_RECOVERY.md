# Восстановление текста ответа чата

Дата: 2026-10-17.

Раньше структурированный ответ без верхнеуровневого строкового `reply` или
`response` заменялся сообщением об ошибке, даже если текст находился в другом
поле. Теперь `ChatReplyJson` сохраняет приоритет этих двух полей, а при их
отсутствии извлекает текст из произвольно названных полей, вложенных объектов и
массивов. Несколько фрагментов соединяются переводами строк. Поддерживаются
одинарные кавычки, частично сформированные строки, значения без кавычек,
JSON-ограждения Markdown и обычный текст. Это терпимое извлечение для показа,
а не валидация JSON.

Имя поля само по себе не запрещает показ текста: даже читаемая фраза в `role`
или `emoji` сохраняется. Известные служебные значения (`role: assistant`,
`intent: calendar_add`) и отдельные значки в полях метаданных не подменяют
ответ. Неизвестный неструктурированный формат остаётся обычным текстом.
Универсальное определение смысла любого повреждённого формата не гарантируется.

Если текста нет, `ChatReplyTextStream` допускает один повтор через
`ChatContextSession` с временной системной просьбой ответить обычным текстом.
Повтор получает исходную историю без неудачного ответа и без второго сообщения
пользователя. Дополнительная инструкция входит в реально подсчитываемый промпт;
проверки вместимости контекста и пользовательский выбор истории сохраняются.
Второй пустой ответ даёт прежнее сообщение:
«Не удалось разобрать ответ модели. Попробуйте изменить запрос.»

Оба прохода используют один `ChatResponseWriter`. Первая ошибка не выводится
и не сохраняется перед повтором. Озвучивание в `ChatViewModel` вызывается после
получения окончательного текста. Отмена прерывает текущий проход и не запускает
следующий; ошибки самого движка обрабатываются существующим путём без повторов.
Перед повтором проверяются текущие чат и модель.

Для ответа без текста добавлен `CHAT_RAW_MODEL_RESPONSE` только в debug-сборке:
длина ответа и первые 3500 символов частями по 800 символов. Сохраняется
`CHAT_REPLY_PARSE_ERROR`. Это позволит увидеть фактический формат при следующем
воспроизведении. Исходные ответы из ошибок 21:11:10 и 21:13:26 восстановить из
старого logcat нельзя.

Календарный путь не использует восстановление и повтор чата; строгий разбор
команд не расширялся этой доработкой. Существовавшие до неё изменения календаря
в рабочем дереве сохранены.

символу, приоритет `reply`/`response`, обычный потоковый текст, частичные строки
и Unicode, отсутствие третьей попытки, отмена во время обоих проходов,
распространение ошибок движка, единственная запись окончательного ответа,
