# Последнее созданное событие: дополнение к V12.56

Область: один пользовательский запрос. Изменяются правила и ручные материалы;
контракт JSON и рабочий код приложения остаются прежними. Дополнение хранится
отдельно от уже обученной V12.56; новый номер модели пока не назначен.

## Выбор команды и события

- «Измени последнее событие», «исправь последнюю запись», «у последнего
  добавленного события» означают последнее **созданное** событие. Использовать
  `calendar_update` и `params.target: {"use_last_created":true}`. Дата начала
  события не определяет порядок создания. Не подставлять выдуманное название.
- «Найди последнее событие и измени в нём время», «отыщи последнюю запись и
  перенеси её», «сначала найди последнее созданное событие, потом исправь его»
  в одном запросе тоже означают один `calendar_update`. Слово «найди» описывает
  выбор цели изменения, отдельная команда поиска не нужна. Выдавать один JSON.
- Если правка не названа, например «измени последнее событие», передавать
  `changes: {}`. Приложение открывает редактирование выбранного события.
  Не придумывать новое время, дату, название, значение или длительность.
- Если в текущем запросе названо конкретное событие, в том числе «из найденных
  измени Осмотр сцены», использовать `target.query` с этим названием. Приложение
  повторно разрешает цель по запросу; несколько совпадений требуют выбора.
  Это не автоматический доступ модели к результатам предыдущего поиска.
- Указанный период поиска относится к `target.range_start`/`target.range_end`;
  новая дата относится к `changes.date`. Не смешивать исходный период и дату
  переноса. Не сочетать `query` с `use_last_created`.
- Не выдавать `calendar_last`, `use_last_match`, `use_last_referenced`,
  `event_id` или `use_last_in_range` для этих команд изменения: их не принимает
  существующий контракт `calendar_update`. Не подменять последнее найденное
  событие последним созданным.

Отдельный запрос «найди последнее событие», а затем другое сообщение «измени
в нём время» не входит в это дополнение. В режиме календаря модель получает
только текущий запрос. Фраза без названия «измени найденное событие» сама по
себе не определяет цель; нельзя обучать её на выдуманном названии или на
`use_last_created`. Обычный поиск по названию остаётся `calendar_search`.

## Изменяемые поля и ответ

`changes` содержит только названные правки. Нулевое значение — `value: 0`,
очистка значения — `clear_value: true`; отсутствие правки значения сохраняет
его. Половины часа без части суток сохраняют правило V12.56: полпятого = 16:30,
полдевятого = 20:30; полдевятого утра = 08:30. Цифровое время остаётся в `params`,
относительные словесные формы без части суток — только в `reply`.

Существующий обучающий контракт требует префикс «Событие изменено:» у полного
`calendar_update`; в дополнении он сохранён. Текст модели не подтверждает
запись в базу: исполнение, выбор при неоднозначности и подтверждение правок
принадлежат приложению. У команды с пустым `changes` этого префикса нет.

```json
{"intent":"calendar_update","reply":"Событие изменено: время последнего созданного события в половине пятого.","params":{"target":{"use_last_created":true},"changes":{"time":"16:30"}}}
```

## Материалы

[Ручной реестр](calendar_assistant_last_event_manual.json) содержит 42 запроса
и полных эталонных JSON-ответа с общим дословным системным контекстом. При
сериализации контекст копируется в каждый разговор. Тексты и ответы не
генерируются скриптом. Три группы имеют по 10 train, 2 validation и 2 holdout.

`tools/calendar_sft/prepare_last_event.py` добавляет их в отдельную копию
`docs/calendar_sft_v12_56_last_event`. Все исходные строки и пять holdout-файлов
V12.56 сохраняются побайтно; новый `last_event_holdout.jsonl` не участвует в
обучении. Обучение и обновление GGUF этим дополнением не запускаются.

## Проверено 13 сентября 2026 года

- 47 Python-тестов прошли: новый набор, сохранность исходных данных,
  проверки V12.56 и общего контракта.
- Android-проверка `LastEventManualExamplesTest` пропустила все 42 ручных
  ответа через существующие `AssistantResponseParser` и `CalendarCommandMapper`:
  выбор цели, период и поля изменений сохранились. Дополнительная проверка
  подтвердила отклонение выдуманных команд, псевдонимов и конфликтующих целей.
  Вместе с `AssistantResponseParserTest` Gradle завершился `BUILD SUCCESSFUL`.
- Все 3570 строк дополненного набора помещаются в лимит 256 токенов без
  обрезания. Новые строки занимают максимум 185 токенов; маска обучения
  только на ответе сохранена. См. [отчёт токенизации](calendar_sft_v12_56_last_event/tokenization_report.json).

Рабочий код приложения не изменялся. Это проверка эталонных ответов и их
совместимости, а не качества генерации модели. Новое обучение, holdout-прогон
модели, сборка GGUF и проверка на телефоне в этой задаче не выполнялись.
