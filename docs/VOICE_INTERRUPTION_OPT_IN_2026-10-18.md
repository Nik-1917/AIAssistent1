# Необязательное перебивание ответа в режимах активации

Дата: 18.10.2026.

## Итоговое правило

Для «Активации по имени» и «Персонального слова v3» доступен один сохраняемый переключатель **«Прерывать ответ голосом»**. Значение по умолчанию — **выключено**. Выбор общий для обоих способов активации. При переходе в обычный голосовой ввод сохранённое значение не разрешает перебивание; переключатель там не показывается.

При выключении микрофон приостановлен во время озвучивания; перед первым звуком ожидается освобождение реально работающей записи. Между ответами имя и персональное слово продолжают работать по текущим правилам голосового режима. При включении разрешено только подтверждённое обращение по имени или персональное слово с последующей отдельной командой. Нажатие микрофона продолжает останавливать диктора вручную.

## Хранение и синхронизация

- `AudioPreferences.allowVoiceInterruption` хранит выбор пользователя; значение по умолчанию `false`.
- Фактическое разрешение `voiceInterruptionEnabled` требует одновременно включённого переключателя и способа активации, отличного от `DIRECT`. Все существующие проверки захвата и принятия перебивания используют это вычисляемое правило.
- Новый ключ DataStore — `activation_voice_interruption_enabled`, по умолчанию `false`. Старый `barge_in_enabled` не читается и не переносится: его прежнее значение `true` не включает новую настройку после обновления.
- Изменение значения атомарно увеличивает ревизию аудиополитики. Эффективное разрешение включено в снимок `VoiceInputPolicy`, поэтому даже готовность/событие старого сеанса не подходит для новой настройки. Повторное сохранение того же значения не перезапускает сеанс.
- Существующий наблюдатель политики закрывает старую запись и запускает разрешённый текущими настройками путь. Подготовка вывода повторно проверяет настройки после каждого асинхронного перехода: выключение во время ожидания готовности требует освобождения микрофона; включение во время его закрытия требует готового захвата активации.

## Защита и совместимость

Сохранены AEC/NS, подготовка эталона диктора до звука, привязка временных меток, фильтрация голоса/текста диктора, проверка Voice ID и двухэтапный сценарий персонального слова v3. Изменение переключателя не сбрасывает голосовой профиль, запись персонального слова или выбранный способ активации.

Этот этап уточняет прежнее автоматическое разрешение для имени/v3, описанное в `VOICE_INTERRUPTION_BY_ACTIVATION_2026-10-18.md`. Результаты прошлой ручной проверки относятся к прежнему правилу; они не считаются новой проверкой выключенного переключателя.

## Проверки

Добавлены проверки выключенного состояния во всех режимах, сохранения общего выбора, восстановления обоих значений из реального файла DataStore, игнорирования старого ключа, ревизии политики, ручного ввода при обоих состояниях и переключения во время подготовки звука. UI-проверка использует отдельный DataStore и не затрагивает настройки приложения, микрофон или модели.
