# Batch Size и шкала Top K

Дата: 2026-10-01.

## Настройки

Во вкладках «Модель календарь» и «Модель чат» добавлены:

- Шкала Top K: целые значения от 1 до 100, метка и подпись значения по умолчанию 20.
- Переключатель режима Batch Size: «Авто» / «Вручную». По умолчанию включено «Авто».
- Шкала размера пакета: 64, 128, 256, 512, 1024 токена; позиции больше размера контекста недоступны. В режиме «Авто» шкала показывает вычисленное значение и недоступна для ручного перемещения.
- Метка значения по умолчанию: 256 для календаря и 512 для чата, с подписью «Авто».

Формула автоматического выбора: `min(512, contextSize - maxTokens)`. Сохранённые пользовательские настройки контекста и ответа по-прежнему согласованы 2:1. Поэтому календарные значения 512/256 дают пакет 256; значения чата 2048/1024 дают пакет 512.

Ручное значение хранится отдельно от режима. Включение «Авто» не стирает его. При уменьшении размера контекста слишком большое ручное значение ограничивается допустимыми положениями. Некорректное значение из хранилища приводится к ближайшему разрешённому; при равном расстоянии выбирается меньшее.

Batch Size определяет максимальный размер порции входных токенов при обработке вопроса. Полный вход может занимать несколько порций. Этот параметр не увеличивает окно контекста, не обрезает входной prompt и сам по себе не резервирует место под ответ. Формула — ограниченное правило приложения; оптимальную производительность на конкретном устройстве она не гарантирует.

## Хранение и применение

Для каждого файла модели и профиля DataStore сохраняет `batchSizeAuto` и `batchSize` вместе с остальными параметрами одной транзакцией. Отсутствующие ключи получают режим «Авто» и профильное ручное значение по умолчанию. Top K также остаётся отдельным для каждого профиля; его сохранённое значение ограничивается диапазоном 1–100.

Секундный таймер, завершающая запись при закрытии вкладки и защита от запоздавших уведомлений DataStore сохранены. Переключение вкладки настроек не переключает режим разговора.

Нативные `n_batch` и `n_ctx` задаются при создании контекста Llamatik. Поэтому движок запоминает конфигурацию загруженного контекста: размер контекста, фактический Batch Size и GPU-слои. При изменении этих значений повторная загрузка выполняется в `ensureLoaded()` перед следующим запросом. Сохранение настроек само по себе модель не выгружает. Переход «Авто» → «Вручную» с тем же фактическим размером пакета повторной загрузки не требует.

Загрузка и генерация используют общий `modelMutex`. Генерация держит его до завершения нативного потока и его завершающей отмены. Ожидающая повторная загрузка не может освободить контекст текущего ответа. `updateParams()` во время генерации сохраняет будущие параметры, не передавая их в работающий native runtime. Изменения обычных параметров сэмплирования на свободном движке применяются без повторной загрузки.

Временная выгрузка использует прежний `releaseModel()` и сохраняет executor. Окончательный `close()` остаётся обязанностью владельца движка. Ошибка повторной загрузки очищает сведения о применённых параметрах, чтобы следующий запрос мог повторить загрузку. Поддержка нескольких одновременно работающих экземпляров движка этим изменением не добавлена.

## Почему так

Пакет ограничивается доступным окном и фиксированным потолком автоматического режима. Пользователь видит фактическое значение, а отдельные профили сохраняют независимую настройку. Отложенная повторная загрузка не выполняется на каждом движении шкалы и не прерывает ответ. Сравнение фактической конфигурации исключает повторные загрузки при изменении только способа выбора того же значения.

## Проверки

Тесты покрывают формулу и границы, позиции ручной шкалы, переключение режимов, нормализацию старых значений, независимость профилей, сохранение и восстановление из файла DataStore. Тесты движка используют настоящий executor и управляемую нативную границу: проверяют отложенную повторную загрузку, отсутствие лишних загрузок, ожидание завершения генерации и повтор после ошибки загрузки.

Результаты запуска тестов, сборки и lint фиксируются в итоговом отчёте. JVM-проверки не подтверждают производительность или нативный GGUF-инференс на физическом устройстве.
