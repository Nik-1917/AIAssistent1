# Необязательное поле params у обычной реплики

Изменение от 2026-10-17: `AssistantResponseParser.parseResult` допускает отсутствие поля `params` только при `intent: "chat"` или `intent: "chat_reply"`.

Оба варианта дают одинаковый результат разбора с исходным текстом `reply` и `AssistantResponse.params == null`:

```json
{"intent":"chat","reply":"Уточните запрос."}
{"intent":"chat","reply":"Уточните запрос.","params":{}}
```

Для `chat_reply` действуют те же правила. Если `params` передано, оно по-прежнему должно быть пустым объектом: `null`, массивы, строки, числа, логические значения и неизвестные поля отклоняются. Обязательная непустая строка `reply`, проверка неизвестных и повторяющихся ключей, а также строгий синтаксис JSON сохраняются.

У `calendar_add`, `calendar_search` и `calendar_sum` объект `params` остаётся обязательным. Проверки полей, типов, дат и интервалов проходят прежний путь. Пустой объект по-прежнему означает незаполненные параметры команды; его обработка не меняется.

Обычная реплика не создаёт черновик, поэтому отображается карточкой сообщения. `ChatViewModel` сохраняет исходный `reply` и передаёт его в существующий механизм автозвука. Это позволяет показать и озвучить корректную обычную реплику, даже если модель опустила пустой объект.

`AssistantResponseParserTest` проверяет оба intent с отсутствующим и пустым `params`, точное сохранение текста, отклонение неверно переданного поля и сохранение обязательного объекта у календарных команд. UI-пример `replyWithOmittedParamsKeepsTextActionsAndPlaybackText` обновлён на фактически отсутствующее поле.
