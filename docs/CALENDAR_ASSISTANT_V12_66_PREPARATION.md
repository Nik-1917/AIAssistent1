# V12.66: подготовка создания и поиска событий

Подготовлено 4 октября 2026 года для следующего обучения Qwen3.5-2B.
Последнее уточнение владельца: убрать **«напомни» вне `calendar_add`**;
вопросы о дате и времени оставить, **«найди» сохранить**.

## Что изменено

В [правилах V12.66](CALENDAR_ASSISTANT_V12_66_INTENT_ROUTING.md) и
[активном контракте подготовки](CALENDAR_ASSISTANT_TRAINING_SPEC.md)
просьба напомнить о действии закреплена за созданием, включая вежливые
вопросы и неполные команды. Поиск обучается на «найди», «покажи»,
«что у меня», «посмотри в календаре». Обычные вопросы сохраняют `chat`.
Составные изменения и существительное «напоминание» в названиях сохранены.
Это устраняет конфликт учебных формулировок; качество будущей модели
нужно измерить после обучения.

Четыре пользовательские формулировки изменены вручную. Их контекст,
`intent`, `reply`, `params`, идентификаторы и прочие поля сохранены:

| Было | Стало |
| --- | --- |
| Можешь напоминать мне о главных ценностях? | Можешь помогать мне помнить о главных ценностях? |
| Напомни вчерашнее число. | Скажи вчерашнее число. |
| Напомни, какое время получится через одну минуту? | Скажи, какое время получится через одну минуту? |
| Напомни мне, сколько получится времени через полчаса? | Скажи мне, сколько получится времени через полчаса? |

Точные позиции: [ручной реестр](calendar_v12_66_manual/input_repairs.json).
Три изменения относятся к train, одно к копии offset_reply_holdout.
Ни один прежний пример не удалён: сохранены все 291 пример `chat`,
171 пример со словами «найди», «найдите», «найти» и все 7196 прежних ответов.
7192 унаследованные строки остались побайтово прежними. Исходная V12.65
и остальные исторические наборы не перезаписывались.

## Ручной набор и проверка

[Новые исходники](calendar_v12_66_manual/) содержат 108 буквальных примеров:
60 train (30 создания и 30 поиска), 20 validation и 28 независимых holdout.
Есть неполные просьбы, вежливые вопросы, разные позиции полей, смещения,
длительность и значение, границы года и февраля. В validation и holdout
добавлены также обычные вопросы о дате и времени. Полное покрытие всех
русских формулировок не заявляется.

[Готовые данные](calendar_sft_v12_66/): **6009 train, 762 validation**,
новый intent_holdout из 28 строк; прежние проверочные наборы сохранены.
Всего 7304 строки JSONL. Сетка 1440 времён унаследована без изменений.

- Нарушений «глагол напомнить вне `calendar_add`» в запросах и ответах нет.
- Все 5493 строки с известным временем прошли проверку смысла и формы `reply`.
  Ошибка `12:15` → «двенадцать минут первого» по-прежнему отклоняется.
- 20 новых тестов прошли; 71 прежний функциональный тест времени и оценки
  прошёл. Два исторических теста полного снимка V12.64/V12.65 исключены
  из этого прогона: их старые хеши не соответствуют текущему checkout
  и разрешённому обновлению активного TRAINING_SPEC. Старые проверки
  и реестры не изменены. Текущая повторная сборка V12.66 прошла;
  хеши всех 1386 защищённых исходных файлов совпали.
- Токенизатор Qwen3.5-2B: 21912 кодирований в трёх форматах, максимум
  216 / 219 / 211 токенов при лимите 384, обрезаний нет, маска обучения
  включает только ответ assistant. Веса модели не загружались.
- Подготовительный запуск обучения `preflight` прошёл. Для последующей
  независимой оценки сохранены 56 запросов: 28 примеров в двух форматах.

## Оценка и следующее обучение

Оценщик V12.66 сохраняет проверки времени V12.65 и добавляет матрицу
ошибок всех шести intent. Неверная команда не получает зачёт. Некорректный
тип `intent` учитывается как ошибка, а не прерывает оценку.

Для выбора checkpoint используются 116 разработческих примеров в двух
форматах: 232 проверки. Прежние 96 примеров сохранены. Приоритеты:
средняя доля полностью верных ответов по intent, точность intent,
согласованность времени, точность параметров. Holdout в выбор не входит.
Запланированы 1128 шагов; оценки на 188, 376, 564, 752, 940, 1128.

Новые инструменты находятся в `tools/calendar_sft/*v12_66*`.
Проверка без обучения из корня проекта:

```powershell
.\build\calendar_sft_qwen35_venv\Scripts\python.exe -X utf8 -B tools/calendar_sft/prepare_v12_66.py --check-only
.\build\calendar_sft_qwen35_venv\Scripts\python.exe -X utf8 -B -m unittest discover -s tools/calendar_sft -p test_v12_66.py -v
.\build\calendar_sft_qwen35_venv\Scripts\python.exe -X utf8 -B tools/calendar_sft/train_v12_66.py --mode preflight
```

Доказательства: `build/calendar_v12_66_preparation/` и
`build/calendar_v12_66_qwen35/qwen35_2b/preflight.json`.
Режим по умолчанию — `preflight`. Обучение, GPU smoke, генерация ответов,
сборка GGUF и запуск на телефоне **не выполнялись**. Android-код не изменён.
Согласованность данных не доказывает, что следующая модель уже исправлена.
