# Первый запуск локальной модели

При открытии календаря или чата приложение проверяет состояние локального движка. В окне «ИИ не запущен» две кнопки расположены в один ряд. Слева «Выбрать модель» открывает список GGUF и импорт файлов. Справа «Запустить» загружает выбранную модель. Если модель ещё не выбрана, эта кнопка открывает список.

Начало надписи «Выбрать модель» выровнено по левому краю текста подсказки и строки выбранной модели выше. В окне «ИИ не запущен» отступы от окна до границ содержимого одинаковые со всех сторон: 24 dp, заданные внутренним отступом `AlertDialog`. Это относится к началу текста слева, заголовку сверху, правому краю иконки крестика и кнопки «Запустить», нижнему краю кнопки «Запустить». На подключённом Redmi с плотностью 440 dpi это 66 пикселей. Кнопки внизу имеют минимальную высоту 48 dp. Между ними остаётся промежуток не менее 6 dp. Область нажатия крестика расширяется средствами Compose до стандартных 48×48 dp и не увеличивает отступы разметки.

Крестик справа сверху закрывает окно и оставляет пользователя на текущем экране. Повторная попытка выполнить действие с ИИ без готовой модели снова показывает окно запуска. Подробности: [закрытие окна запуска ИИ](MODEL_STARTUP_DIALOG_CLOSE.md).

Сразу под заголовком видна подсказка «Первый запуск может занять до минуты.». Следующая строка показывает имя модели и размер её GGUF из списка моделей. На Redmi файл Qwen3 размером 639 442 784 байта отображается как «Выбрана модель - Qwen3-06B 639 МБ». Для других моделей используется имя файла без расширения GGUF.

## От кнопки запуска до первой команды календаря

1. После нажатия «Запустить» заголовок «ИИ не запущен», подсказка и строка выбранной модели остаются в том же окне. Обе кнопки скрываются, а на их месте движется полоска загрузки. Высота области кнопок сохраняется, поэтому окно не меняет размер при начале запуска. Подробности: [анимация запуска на месте кнопок](MODEL_STARTUP_INLINE_PROGRESS.md).
2. Приложение запускает службу переднего плана на время загрузки. Движок определяет путь к файлу, читает длину контекста из его метаданных и подключается к рабочему процессу `:llm`.
3. В режиме «Авто» движок проверяет совместимость Vulkan, затем при необходимости OpenCL. По метаданным модели и доступной памяти он выбирает число слоёв для GPU. Если подходящего GPU нет или инициализация обоих вариантов завершилась ошибкой, используется CPU.
4. В рабочем процессе llama.cpp открывает GGUF с отображением файла в память, размещает веса и создаёт стартовый контекст. Для него запрашиваются 512 токенов и пакет до 64 токенов. При первом таком размещении на GPU движок выполняет короткую проверку обработки входа и генерации, затем очищает контекст проверки.
5. Когда рабочий процесс подтверждает готовность, окно закрывается. Первая команда календаря уже использует загруженные веса. Приложение собирает запрос с инструкциями календаря, подсчитывает токены, при необходимости меняет размер контекста и запускает генерацию. При команде создания события календарь разбирает ответ модели и подготавливает черновик.
6. Чат и выжимки используют тот же экземпляр движка. Каждый запрос получает свои параметры. При прежнем размещении слоёв пересоздание рабочего контекста сохраняет веса в памяти.

Окно закрывается сразу после подтверждения готовности нативного контекста в процессе `:llm`. При ошибке окно показывает причину и снова предлагает выбрать модель или повторить запуск.

Одна главная Activity и её ViewModel обслуживают оба экрана и выжимки. При сворачивании и пересоздании экрана приложение сохраняет привязку к рабочему процессу и загруженную модель. При окончательном закрытии экрана или удалении задачи приложение освобождает нативный контекст и веса. Выбор другого файла начинает новую сессию с выбранной моделью. Если Android завершает рабочий процесс, приложение возвращает окно запуска.

## Проверка на Redmi Note 11E Pro, 25 ноября 2026

На Android 13 с Adreno 619 кнопка запуска открыла выбранный файл `calendar-assistant-v12.67-Qwen3-0.6B-Q8_0.gguf`. В одном из запусков из чата нативная инициализация заняла 42,7 секунды. В отдельном прогоне календарь, чат и выжимка последовательно выполнились через OpenCL с 29 из 29 слоёв на GPU. Нативный журнал показал одну загрузку весов на все три задачи. При явном выборе CPU тот же набор задач также прошёл с одной загрузкой весов.

Проверены переходы между календарём и чатом, пересоздание экрана, сворачивание, удаление задачи и возврат окна запуска после потери процесса модели. При серии принудительных завершений в отдельных тестовых запусках MIUI временно отклоняла создание рабочего процесса. Окно показывало «Android не запустил рабочий процесс модели. Повторите запуск чуть позже.» и предлагало повторить запуск.

## Проверка кнопок, 26 ноября 2026

На Redmi Note 11E Pro при системном масштабе шрифта 125 % кнопки «Выбрать модель» и «Запустить» поместились в один ряд. Тест интерфейса подтвердил, что обе подписи видны целиком, список файлов открывается, а при запуске под заголовком отображается полоска загрузки.

## Выравнивание кнопок, 27 ноября 2026

Приложение и тестовый APK успешно собраны командой `./gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest --console=plain`. Обновление установлено на Redmi с сохранением данных. По иерархии интерфейса измерены отступы слева, сверху, справа у крестика и кнопки «Запустить», снизу: все равны 66 пикселям при плотности 440 dpi, то есть 24 dp. Центры заголовка и крестика совпадают. MIUI заблокировала запуск тестовой Activity из фона и автоматическую инъекцию нажатия; эти проверки не считаются пройденными. Точные границы элементов и ограничения проверки приведены в [описании закрытия окна](MODEL_STARTUP_DIALOG_CLOSE.md#проверка).
