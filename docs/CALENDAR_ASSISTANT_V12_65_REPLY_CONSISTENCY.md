# V12.65: одинаковое время в параметрах и reply

Правила подготовки V12.65, согласованные 4 октября 2026 года. Действуют для
добавления и изменения события, включая оба известных конца интервала.

## Смысл времени

Входное время, время в параметрах и произнесённое время обозначают один
момент. Сначала определяется точная дата и время по запросу и текущему
времени из system. Эти значения записываются в параметры и передаются
словами в reply. Порядок полей выходного JSON остаётся прежним.

Часы не становятся количеством минут. Для HH:MM количество прошедших
минут равно MM. Название следующего часа определяется из HH отдельно.
Для форм «без» число оставшихся минут равно 60 − MM. Округления нет.

| Параметры | Правильная фраза |
| --- | --- |
| 11:15 | в четверть двенадцатого |
| 12:12 | в двенадцать минут первого |
| 12:14 | в четырнадцать минут первого |
| 12:15 | в четверть первого |
| 12:16 | в шестнадцать минут первого |
| 00:15 | в четверть первого |
| 23:15 | в четверть двенадцатого |

«В двенадцать минут первого» не соответствует 12:15: в этой фразе
двенадцать — минуты. «В четверть одиннадцатого» не соответствует 11:15.
Ошибочные варианты служат контрпримерами правил и тестов; они не являются
целевыми assistant-ответами SFT.

Произношение всех 1440 минут суток сохраняет
[формы V12.62](CALENDAR_ASSISTANT_V12_62_REPLY_CLOCK.md): :15 — «четверть»,
:30 — «в половине», :45 — «без четверти». Сохраняются склонение, правило
точного часа и отсутствие уточнений «утра/дня/вечера/ночи» в reply.
12-часовая форма речи не меняет 24-часовое значение параметров.

## Роли чисел и относительное время

«Через N минут/часов» задаёт начало: текущее время из system плюс смещение,
с переносом даты через полночь. «На N минут/часов» задаёт duration_min.
Длительность, ценность и числа в названии не подменяют минуты начала.
При текущем 12:14 «через минуту на двенадцать минут» даёт начало 12:15,
duration_min=12 и фразу «в четверть первого на двенадцать минут».

Это правило не зависит от положения названия, даты, времени, длительности
и ценности в запросе. Для изменения события произносится новое время из
changes.time. Для интервала сохраняются оба конца и их даты.

Если время известно, reply называет его, в том числе когда отсутствует
название: «Название события не указано. Время: в четверть первого».
Если время неизвестно, оно остаётся неизвестным и в параметрах, и в reply.
Дословные названия и запросы поиска не редактируются ради формы времени.

## Проверка

В новых копиях данных исправляются только перечисленные в ручном реестре
reply. Исходные версии сохраняются. Проверяются все известные начала,
окончания и изменения времени, а не только отдельная временная категория.

Оценка модели разделяет: точность параметров относительно эталона, смысл
времени в reply, согласованность reply с фактически выданными параметрами,
форму речи и арифметику смещения. Верные параметры с неверным reply —
неуспешный пример. Совпадение двух ошибочных ответов также не является
проверкой качества.

Разработческие примеры участвуют в выборе контрольной точки. Независимый
holdout не участвует в обучении и выборе контрольной точки. Известный
сбой Qwen3.5-2B учитывается отдельно как регрессия, а не как новый holdout.

Markdown описывает подготовку данных и оценивание; приложение не вставляет
этот документ в system. Изменение правил само по себе не меняет GGUF.
Подтверждение результата требует следующего обучения, генерации и проверки
готового GGUF в приложении.
