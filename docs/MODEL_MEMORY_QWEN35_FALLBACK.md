# Расчёт памяти Qwen3.5 и неизвестных архитектур

Дата: 2026-10-03.

## Изменение

`ModelMemoryCalculator` теперь выбирает отдельный профиль `qwen35`. Раньше корректный GGUF этой архитектуры отклонялся списком поддерживаемых имён ещё до нативной загрузки. `GgufMetadataReader` дополнительно читает параметры SSM, интервал полных attention-слоёв, ограниченную маску рекуррентных слоёв и число NextN-слоёв. Веса и массив токенизатора не загружаются.

Для выданного `calendar-assistant-v12.63-Qwen3.5-2B-Q4_K_M.gguf` расчёт учитывает:

- KV-кеш шести полных attention-слоёв, с FP32-запасом и округлением контекста вверх до 256.
- Постоянное FP32-состояние 18 рекуррентных слоёв: свёртка `(kernel − 1) × (inner + 2 × groups × state)` и матрица `state × inner`.
- **17 слотов состояния на слой:** Llamatik 1.10.1 задаёт `n_rs_seq = 16` и одну последовательность даже без MTP-весов. Это резерв отката, который нельзя пропускать. Контракт нужно перепроверять при обновлении Llamatik.
- Рабочие буферы Gated DeltaNet для нефузированного исполнения: FP32-векторы, матрицы чанков по 64 токена и временные копии состояния. Этот резерв растёт с batch; постоянное состояние учитывается по слоям.
- Прежние затраты на веса, активации, логиты, полное attention, GPU-копию и резерв RAM устройства.

Явная маска слоёв имеет приоритет над интервалом. При отсутствии обоих используется интервал 4 из llama.cpp. NextN-слои консервативно учитываются как дополнительные полные attention-слои. Некорректные размеры, маски, типы и переполнения не превращаются в fallback.

## Fallback

Неизвестное имя архитектуры при пригодных общих метаданных больше не является причиной запрета загрузки. Для него включается `CONSERVATIVE_FALLBACK`:

- Контекст ограничен 2048 токенами и дополнительно текущим бюджетом RAM и пределом GGUF.
- KV-кеш оценивается для всех слоёв и всех attention-голов, без уменьшения на GQA.
- Рабочие буферы получают двойной запас плюс 256 МиБ; для весов резервируется ещё одна копия файла.
- При наличии пригодных SSM-параметров дополнительно учитывается состояние всех слоёв.
- В пояснении настроек прямо указано, что оценка приблизительная и использует повышенный запас.

Это эвристика для файлов с читаемыми общими размерами (слои, embedding, FFN, attention, vocabulary), а не универсальная формула для любой будущей архитектуры. Недостаточные или повреждённые метаданные, недоступные показания RAM, `lowMemory`, арифметическое переполнение и недостаточный бюджет по-прежнему блокируют загрузку. Поддержка самой архитектуры нативной библиотекой проверяется при загрузке.

Прямой расчёт и обратный расчёт максимального размера файла используют один профиль и одну формулу весов. Повторная проверка RAM перед нативной загрузкой сохранена. Соотношение контекст/ответ и существующие профили обычных моделей не изменены.

## Проверка

Добавлены проверки фактических метаданных Qwen3.5-2B, независимых приростов KV/SSM, 17 слотов состояния, масок и порядка байтов, повреждённых GGUF, переполнений, RAM на границе допустимого, обратного расчёта и ограничения fallback перед нативной загрузкой.

Инструментальный тест запускается только с явным именем импортированной модели, использует контекст 512, CPU и batch 64, проверяет загрузку и получение текста. Он не сохраняет настройки и не выполняет календарные команды.

Итоговая проверка 2026-10-03:

- `:app:testDebugUnitTest`: **498 тестов, 0 ошибок, падений и пропусков**.
- `:app:assembleDebug`, `:app:assembleDebugAndroidTest`, `:app:lintDebug`: успешно. Lint: 0 ошибок, 55 предупреждений и 2 подсказки; замечаний в изменённых файлах расчёта памяти и новом тесте телефона нет.
- APK установлен на физический телефон `2201116SC`, serial `34ae334ef3fb`. SHA-256 установленного APK совпал со сборкой: `3fd128ca9169e4aaf6955ea8d03490570a8eb930b999b0325317633b9a10fd97`.
- `Qwen35MemoryInstrumentedTest`: **1 тест, успешно**, 20,737 секунды. CPU, 4 потока, контекст 512, batch 64, максимум ответа 128. Модель вернула «Проверка завершена.»; движок штатно закрыт.
- Расчёт при автоматическом batch также вернул `ESTIMATED`, максимум 6656 на момент снимка RAM. Это результат оценки, а не проверка генерации на максимальном контексте.

До финального запуска приложение было удалено через лаунчер и переустановлено вне этой проверки. После согласования свободного телефона установленный APK проверен по хешу, GGUF восстановлен из Download через `.part`, проверку SHA-256 и переименование без перезаписи. Ошибка возвращаемого типа первого тестового метода JUnit исправлена в тестовом APK до успешного запуска. Настройки пользователя тест не сохранял.

Логи и машинный отчёт: `build/qwen35_memory_verification/verification.json`, `phone-smoke.json`, `device-test-verified.log`, `gradle-final.log`. Проверены загрузка и получение текста; качество календарных команд и генерация на максимальном контексте этим тестом не оценивались. Оценка памяти не гарантирует отсутствие OOM при изменении нагрузки устройства.
