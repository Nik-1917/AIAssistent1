# Потоки CPU в настройках моделей

Дата: 2026-10-02.

## Поведение

Во вкладках «Модель календарь» и «Модель чат» добавлены переключатель «Авто» / «Вручную» и шкала «Потоки CPU». По умолчанию включено «Авто». Шкала показывает фактическое число потоков, метку автоматического значения и подпись «По умолчанию: N (Авто)».

Автоматический выбор сохраняет прежний алгоритм движка:

| Доступные процессоры | Потоки в режиме Авто |
| --- | --- |
| 1–4 | Число доступных процессоров |
| 5–8 | 4 |
| 9 и больше | 6 |

Ручная шкала имеет целые позиции от 1 до числа процессоров, доступных процессу приложения. Это значение сообщает `Runtime.availableProcessors()`. Оно фиксируется при первом обращении к общему `CpuThreadSettings` и используется одинаково в интерфейсе, начальных значениях и движке. Это не определение количества производительных ядер и не измерение оптимальной скорости.

В режиме «Авто» шкала недоступна для ручного изменения. Ручное значение запоминается при переключении режимов. Если доступен один процессор, остаётся одна отключённая позиция 1; отрисовка метки не делит на нулевую длину диапазона.

Под шкалой показано: «Доступно процессоров: N. Число вычислительных потоков CPU при генерации ответа. Новое значение применяется перед следующим запросом.»

## Хранение и применение

`GenerationParams` хранит `cpuThreadsAuto` и `cpuThreads`. Оба поля записываются вместе с остальными параметрами профиля одной транзакцией DataStore. Ключи имеют вид `model_params/<calendar|chat>/<имя модели>/cpuThreadsAuto` и `…/cpuThreads`. Настройки разных моделей и профилей независимы. При отсутствии ключей используется Авто, а начальное ручное значение совпадает с автоматическим значением устройства.

При чтении и сохранении ручное значение ограничивается диапазоном 1..N. Движок дополнительно ограничивает его на нативной границе, в том числе для временных параметров, не прошедших через DataStore. Некорректное число доступных процессоров ограничивается снизу единицей.

Существующий секундный таймер и завершающее сохранение при закрытии вкладки не изменены. Переключение вкладки настроек не меняет режим разговора. Во время генерации действует прежний снимок параметров запроса.

Число потоков передаётся в `LlamaBridge.updateGenerateParams(numThreads = …)`. В используемой Llamatik 1.10.1 этот параметр сохраняется для `cparams.n_threads` при создании нативного контекста. Поэтому фактическое число потоков включено в `NativeConfiguration`. Изменение вызывает повторную загрузку в `ensureLoaded()` перед следующим запросом, после завершения текущей генерации и её очистки. Сохранение настроек само по себе не выгружает модель.

Сравнивается фактическое число потоков: переход между Авто и ручным режимом с тем же значением или изменение запомненного ручного значения при включённом Авто не требуют повторной загрузки. При неизменных параметрах повторный вызов `ensureLoaded()` не обновляет native runtime лишний раз.

Размер пула корутин движка сохраняет прежний автоматический выбор и не меняется ручной шкалой. Настройка управляет вычислительными потоками нативной генерации. Отдельная настройка `n_threads_batch`, обновление библиотеки и изменения нативного C++ этим изменением не добавлены. Временная выгрузка по-прежнему сохраняет executor, окончательное закрытие принадлежит владельцу движка.

## Почему так

Единый расчёт числа потоков исключает расхождение шкалы и значения, передаваемого в Llamatik. Ограничение диапазона не допускает нулевого значения и превышения доступного приложению числа процессоров. Авто сохраняет прежнее поведение существующих установок. Применение перед следующим запросом сохраняет параметры активного ответа, а сравнение фактического значения исключает лишние загрузки модели.

## Проверки

JVM-тесты проверяют границы автоматического алгоритма, ручные ограничения, переключение режимов, значения обоих профилей, независимость сохранения и восстановление из настоящего файла DataStore. Тесты движка с настоящим executor и подменой нативной границы проверяют переданное число потоков, повторную загрузку только при изменении фактического значения и ожидание завершения текущей генерации.

Результаты тестов, сборки APK и lint фиксируются в итоговом отчёте. Эти проверки не подтверждают внешний вид на устройстве, нативный GGUF-инференс, скорость или энергопотребление телефона.
