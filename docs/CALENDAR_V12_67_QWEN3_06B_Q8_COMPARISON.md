# V12.67: Qwen3-0.6B, сравнение F16 / Q4_K_M / Q8_0

По подтверждению пользователя добавлен отдельный сценарий Q8_0. Именно это имя
8-битного формата поддерживает закреплённый llama.cpp; имени Q8_K_M в нём нет.
Системный промпт обязателен во всех проверках.

Сценарий расположен в tools/calendar_sft/qwen3_06b_v12_67_q8/comparison.py,
результаты — в build/calendar_v12_67_qwen3_06b_q8_comparison.
Он ждёт успешного завершения текущего обучения и всех этапов проверки F16/Q4_K_M.
Затем создаёт Q8_0 непосредственно из полученного F16 того же выбранного адаптера.
Повторное обучение не требуется. Существующий замороженный профиль не изменяется.
Это позволяет сравнить влияние формата весов при одинаковом исходном обучении.

## Системный промпт и условия сравнения

Все 412 независимых примеров из 13 наборов выполняются в двух вариантах:

- Android: полный действующий CALENDAR_CONTRACT из SystemPromptProvider.kt,
  заголовок «cегодня … день недели … ответ JSON» и переносы строк из
  LlamatikEngine.buildPrompt.
- Стандартный ChatML: тот же полный контракт, исходный временной заголовок
  эталонного примера и стандартные границы сообщений.

Каждый формат получает 824 одинаковых входа. Дата и время закреплены отдельно
в каждом примере; при переходе к следующему формату они не меняются.
Ответ эталона присутствует в материалах оценки, но не передаётся модели:
вход содержит только system, user и пустое начало assistant.
История разговора и работа на физическом телефоне этим испытанием не проверяются.

Полные тексты и контрольные суммы сохраняются в prepared_inputs.json и freeze.json.
Перед запуском проверяется вместимость полного входа и ответа в контекст 1024:
192 токена для ответа и один дополнительный токен. Усечение запрещено.
Для всех форматов сохраняются одинаковые параметры: temperature=0, top_k=1,
top_p=1, min_p=0, repeat_penalty=1, seed=20261009, без грамматического ограничения,
без сдвига контекста и без повторного использования кеша запросов.
Настольный llama-server запускается на CPU: 12 потоков, один слот, GPU layers=0.

## Проверки и результат

До создания файла проверяются окончание исходного конвейера, закреплённые входы,
контрольные суммы F16/Q4_K_M и выбранного адаптера. Для Q8_0 проверяются тип GGUF,
архитектура qwen3, все 28 слоёв, совпадение имён тензоров и шаблона чата,
загрузка закреплённым llama-server. Лицензия и сведения о модификации копируются
в отдельный каталог выпуска. Проверка загрузки не является оценкой качества.

Ответы Q8_0 сохраняются без исправлений вместе с сырыми ответами сервера.
Сравнение заново оценивает привязанные к модели ответы F16/Q4_K_M/Q8_0
действующим оценщиком v12.67-title-reply-2. Отчёт раздельно показывает оба
варианта подачи: намерение, параметры, даты и время, смысл и стиль reply,
буквальное название, предупреждение о нескольких событиях и полный проход.
Для каждой пары форматов перечисляются потерянные и приобретённые проходы.
Рост размера файла сам по себе не подтверждает улучшение качества.

Итог: quantization_comparison.json. Состояние: pipeline.json.
WAITING_FOR_BASELINE означает, что создание Q8_0 ещё не началось.
COMPLETE означает завершение сравнения; quality_status=FAILURES_FOUND
сохраняет найденные модельные ошибки. Ошибка исходного конвейера или изменение
закреплённых входов останавливает дополнительный сценарий с сохранением журналов.
Повторный запуск поверх существующих материалов запрещён.

Подготовка: Python из build/calendar_sft_qwen35_venv с аргументами
-X utf8 -B tools/calendar_sft/qwen3_06b_v12_67_q8/comparison.py --prepare.
Выполнение: тот же вызов с --run вместо --prepare.
Проверки сценария: test_comparison.py. Их проход подтверждает корректность
сценария и эталонов оценщика, но не качество ещё не созданной модели.
