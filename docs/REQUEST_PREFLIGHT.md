# Проверка запроса перед генерацией

## Причина изменения

До исправления экран включал состояние обработки и добавлял пустой ответ «Думаю…» до проверки запроса. Сервис генерации тоже запускался заранее. В `LlamatikEngine` заведомый отказ по RAM проверялся после подготовки нативного токенизатора и подсчёта токенов. Токены ответа при таком отказе не генерировались, хотя интерфейс уже показывал генерацию.

## Новое поведение

- После отправки запрос занят проверкой; кнопка «Отменить запрос» сохраняет возможность отмены. Повторная отправка и микрофон блокируются прежним флагом обработки.
- После применения параметров и сохранения пользовательского сообщения выполняется `checkModelAvailability`. Заведомый отказ RAM возвращается до запуска сервиса генерации, подготовки токенизатора и обращения к нативной библиотеке.
- Проверка использует прежнюю формулу RAM с минимальным batch 64. Совместимая рабочая конфигурация уже загруженной модели сохраняется даже при новой отрицательной оценке.
- Движок повторяет раннюю проверку внутри самого запроса. При допустимой предварительной оценке остаются точный подсчёт полного входа, проверка контекста, повторная оценка RAM и загрузка модели.
- Сигнал `onReady` приходит после успешной проверки и загрузки, перед декодированием. Только тогда появляется пустой ответ и кнопка «Остановить генерацию».
- При ошибке до готовности пустой ответ не добавляется. Сообщение пользователя остаётся в истории. История, исключения сообщений, настройки календаря и формула оценки RAM не изменены.
- Для раннего отказа размер требуемого контекста неизвестен: `requiredContext = null`. Число не подставляется без токенизации.

Первый замер на телефоне показал ещё одну задержку: проверка целиком заняла 9,14 с, повторная — 21 мс, при нулевых вызовах нативного исполнения. В `GgufMetadataReader` чтение выполнялось мелкими операциями `RandomAccessFile`, с запросами позиции файла и переходами для каждой строки словаря. Теперь используется фиксированный буфер 64 КиБ и логическая позиция: короткие строки пропускаются внутри буфера, большие значения — переходом без чтения всего значения. Ограничения размера метаданных, числа элементов, допустимых типов, границ файла и порядок байтов сохранены. Токены и тензоры не декодируются и не сохраняются в массивы.

Состояние проверки охватывает подготовку запроса и модели. Сервис после предварительной оценки сохраняет работу подготовки в фоне; появление его сессии само по себе не означает начало декодирования.

## Проверки

JVM-тесты проверяют отсутствие подготовки, токенизации, загрузки и декодирования при раннем отказе; порядок сигнала готовности; отмену перед декодированием; сохранение совместимой рабочей конфигурации.

`ChatRequestCheckingUiTest` проверяет смену кнопок, возможность отмены и блокировку ввода во время проверки. `RequestPreflightInstrumentedTest` измеряет первый и повторный отказ на реальном импортированном GGUF с обычной оценкой RAM. Этот тест использует запрещающую нативные вызовы границу и не загружает веса, не выполняет команды календаря и не записывает пользовательские сообщения или настройки. Его время относится к движку, а не к полной задержке от нажатия «Отправить» до показа ошибки.

## Результаты 07.10.2026

- Полный набор JVM-тестов приложения: 560, из них 559 успешны, один тест оценки календарной модели пропущен без входного файла. Ошибок и падений нет.
- `assembleDebug`, `assembleDebugAndroidTest`, `lintDebug` выполнены успешно. Lint: 0 ошибок, 49 предупреждений, 2 подсказки. После корректировки селектора отключённого поля пересобран только тестовый APK.
- На физическом Xiaomi 2201116SC выполнены `RequestPreflightInstrumentedTest` и `ChatRequestCheckingUiTest`: `OK (2 tests)`. Android запрещал запуск тестовой Activity из фона, поэтому она открыта явной командой ADB с тем же Intent. Настройки телефона и разрешения для обхода не менялись.
- Модель: `calendar-assistant-v12.66-Qwen3-4B-Instruct-2507-Q4_K_M.gguf`, 2 497 276 352 байта. Обычная оценка RAM вернула `INSUFFICIENT_MEMORY`.
- Первая проверка доступности в новом процессе: **229,694 мс**; повторная: **22,212 мс**. Прямой запрос движку: чат — **39,708 мс**, календарь — **25,306 мс**. Сигналов готовности и обращений к началу нативного запроса, токенизатору, загрузке и декодированию: **0**.
- До буферизации при той же ранней проверке первый замер был **9 142,124 мс**, повторный — **21,265 мс**. Это отдельные замеры на телефоне, а не гарантия времени на любом устройстве. Полная цепочка отправки, сохранения в Room и показа уведомления этим тестом не измеряется.
- APK установлен обновлением без удаления данных. SHA-256 приложения: `f0571e490129e27a9e9fe3067d4e438fe8beffda60bf5baea857e0bb8389bcb7`; хеш установленного APK совпал со сборкой.
- SHA-256 `settings.preferences_pb` и `calendar_drafts.preferences_pb` до установки и после тестов совпали.

Доказательства сохранены в `build/request-preflight-buffered-validation.log`, `build/request-preflight-device-final.log`, `build/request-preflight-device.json`, `build/request-preflight-device-unbuffered.json`, `build/request-preflight-artifacts.json`, `build/request-preflight-device-before.json` и `build/request-preflight-device-after.json`.

Смена кнопок и их действия проверены в отдельных Compose-компонентах на телефоне; отсутствие преждевременного ответа «Думаю…» проверено по порядку вызовов ViewModel/движка и тестами готовности. Полная ручная отправка из основного экрана и голосовой цикл этими двумя инструментальными тестами не проверялись. Консервативная формула RAM остаётся прежней: ускорение отказа не означает, что загрузка Qwen3-4B теперь разрешена политикой приложения.
