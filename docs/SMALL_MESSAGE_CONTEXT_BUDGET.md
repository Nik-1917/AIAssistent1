# Отдельный режим для сообщений до 322 токенов

Дата: 30 сентября 2026 года.

## Контракт

Пользователь выбрал отдельный режим для нового сообщения **до 322 токенов включительно**. Для него применяется технический запас **32 токена**. Для сообщения от 323 токенов остаётся прежний запас 128. Ступени контекста и максимального ответа сохраняются: 1024/512, 2048/1024, 4096/2048, 8192/4096.

Перед отправкой выполняются два нативных подсчёта одним словарём выбранной GGUF:

1. `actualPromptTokens` — число токенов **окончательной строки**, содержащей системный текст, выбранную историю, новое сообщение, ChatML, дополнительные инструкции и начало ответа. Эта же строка затем передаётся генерации.
2. `userMessageTokens` — число токенов отправляемого текста нового пользователя после обычного `trim()`, до добавления стилевых инструкций. Этот счётчик нужен только для выбора режима ≤322 или ≥323.

Формула:

```text
reserveTokens = userMessageTokens <= 322 ? 32 : 128
requiredTokens = actualPromptTokens + maxOutputTokens + reserveTokens
```

`userMessageTokens` не прибавляется к `actualPromptTokens`. Весь промпт не восстанавливается сложением отдельно токенизированных частей. Если отдельный счётчик отсутствует во внутреннем сценарии, применяется прежний запас 128. Ошибка нативного подсчёта сообщения останавливает подготовку запроса.

Пример пользователя: сообщение условно занимает 30 токенов, а полный окончательный промпт — 90. При ответе до 512 бюджет составляет **90 + 512 + 32 = 634** и помещается в 1024. Это арифметический пример, не замер конкретного текста на телефоне.

При контексте 1024 и ответе 512 полный промпт небольшого сообщения может занимать до **480 токенов**. Само сообщение ≤322 не гарантирует эту вместимость: длинная история может потребовать следующей ступени или привести к отказу при достижении максимума. Черновик при отказе сохраняется.

## Почему так

Запас 32 не заменяет реальные служебные токены: они уже входят в точный `actualPromptTokens`. Он включает внутренний резерв Llamatik 1.10.1 в 16 токенов и ещё 16 токенов для защиты границы. Дополнительно прибавлять внутренние 16 к этим 32 не требуется.

Небольшой режим освобождает 96 токенов входного бюджета по сравнению с прежними 128. Уменьшение рабочего контекста по-прежнему проверяется перед каждым запросом; сохранённый минимум не перезаписывается.

## Реализация

- ViewModel передаёт исходный текст нового пользователя отдельным аргументом через `SendMessageUseCase`. История и стилевые инструкции остаются в сообщениях для полного промпта.
- JNI возвращает размер полного промпта, предел GGUF и отдельный размер сообщения. Для полного промпта сохраняются `add_special=true`, `parse_special=true`, как в нативной генерации. Для отдельного текста сообщения используется `add_special=false`, без автоматических BOS/EOS, с тем же `parse_special=true`.
- Кодировка остаётся той же, что у Llamatik: `GetStringUTFChars`. Подсчёт выполняется в сериализованной операции движка; результат фиксируется вместе со строкой запроса.
- В настройках рабочего контекста показываются отдельно новое сообщение, весь запрос, резерв ответа и технический запас.
- Выжимки конференций и форматирование через `generate()` сохраняют прежний запас 128: эти внутренние сценарии не передают отдельный текст нового сообщения.
