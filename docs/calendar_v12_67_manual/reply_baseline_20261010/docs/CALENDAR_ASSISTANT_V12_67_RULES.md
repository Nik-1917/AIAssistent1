# V12.67: четыре действия ассистента

Согласовано 9 октября 2026 года: `chat`, `calendar_add`, `calendar_search`,
`calendar_sum`. Это полный список действий модели.

## Контракт

Один JSON с полями `intent`, `reply`, `params`. Неизвестные значения
пропускаются; `null`, дополнительные поля и текст вокруг JSON недопустимы.
Полный контракт описан в `CALENDAR_ASSISTANT_TRAINING_SPEC.md`.

- `chat`: обычный ответ, `params: {}`. Вопросы о дате и времени остаются чатом.
- `calendar_add`: известные поля нового события. Просьба «напомни» и её
  глагольные формы относятся к созданию, включая вежливые вопросы и
  неполные просьбы. Без даты и точного времени используется сегодняшняя
  дата. Если указано только точное время, время позже текущего означает
  сегодня, а раньше текущего или равное ему — завтра.
- `calendar_search`: название и известный период поиска. «Найди», «покажи»,
  «что у меня» и «посмотри в календаре» сохраняются. Для всех событий
  используется `query: ""`. Результаты предоставляет приложение.
- `calendar_sum`: запрос суммы сохранённых целых `value` за период,
  с необязательным фильтром названия. Считает приложение; модель не
  сообщает выдуманный числовой итог.

## Сохранённые правила

Порядок полей не меняет действие. Название, длительность, целое значение,
дата, время, начало и конец события сохраняют прежний смысл. `notes` —
необязательный текст внутри создаваемого события.

Периоды поиска и суммы задаются парой местных временных границ:
начало включается, конец не включается. Правила календарных месяцев,
високосных лет, недель, кварталов, получаса и перехода через полночь
сохранены в полном контракте.

Известное время в `reply` соответствует `params`. `12:15` произносится
«в четверть первого». Для относительного времени сначала вычисляется
результат от времени system, затем формируются параметры и ответ.
Неизвестные поля остаются неизвестными; модель не подтверждает запись
в базу.

## Подготовка и проверка

В исходных разговорах V12.66 не переписываются ни пользовательские
формулировки, ни JSON ответов. Состав новой версии определяет проверяемый
реестр позиций `calendar_v12_67_manual/exclusions.json`.
Сборщик только переносит сохранённые строки и обновляет метку контракта.
Русские обучающие предложения не генерируются.

Все наборы V12.67 проверяются отдельным валидатором четырёх действий.
Разработческие примеры и независимые проверочные наборы сохраняются
раздельно. Подготовка, токенизация и проверки не доказывают качество
будущей модели.
