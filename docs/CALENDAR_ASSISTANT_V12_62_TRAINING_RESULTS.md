## Проверка готового GGUF

Зафиксированы 98 запросов: 60 значений минут, ещё 23 часа, шесть запросов
с длительностями/интервалами/разговорным временем, четыре запроса с форматом
системного промпта и ChatML из Android, пять прежних проверок других intent.
Новые запросы написаны вручную и не входят в обучение. Проверка совпадений
с обучающими формулировками пройдена; генерация не получает ожидаемые ответы.

Настольный CPU GGUF проверяется при temperature 0, top-k 1, seed 20260825,
без принудительной JSON-грамматики и без исправления сгенерированного текста.
Отдельно оцениваются JSON/контракт, intent, точные params, params с учётом
регистра названия, время/длительность и соответствие фразы reply времени.

Покрытие 1440 эталонов не означает 1440 проверенных генераций. Проверка с
форматом промпта Android на ПК не является выполнением на физическом телефоне.

`build/calendar_sft_v12_62_gguf_eval_20260929/report.json`.

Все 98 ответов являются JSON-объектами, 97 соответствуют существующему

На исходный запрос «двенадцать часов пятнадцать минут завтра едем» получен
одинаковый правильный ответ с обучающим форматом контекста и с форматом
Android (M15 и A_M15):

```json
{"intent":"calendar_add","reply":"Едем в четверть первого.","params":{"title":"Едем","starts_at":"2026-09-30T12:15"}}
```

Это подтверждено для фиксированного контекста 2026-09-29 10:00 и указанных
настроек генерации. Само по себе это не подтверждает все перефразировки,
другие контексты и работу приложения на телефоне.
