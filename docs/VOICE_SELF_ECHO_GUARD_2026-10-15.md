# Защита от самоперебивания диктором

Дата: 15.10.2026.

## Воспроизведённая ошибка

В обычном голосовом режиме пользователь сообщил цикл: первое слово диктора принималось как новое сообщение, озвучка останавливалась, запускался следующий ответ.

Добавлен отдельный физический тест `VoiceSelfEchoDeviceTest`: штатные TTS, AEC, VAD и ASR; пользователь молчит; события ввода учитываются без отправки в LLM. До исправления тест завершился ошибкой: `commands=1`, `interruptions=1`, ошибок захвата не было. Первый принятый результат содержал 10 символов. Микрофонный PCM и текст распознавания тест не сохраняет.

## Изменения

### Временная привязка вывода

`SherpaOnnxSpeechPlayback` сохраняет один AudioTrack на весь ответ. Синтез по предложениям остаётся. Перед очередным предложением выводятся нулевые образцы до появления двух продвигающихся, согласованных временных меток, максимум 500 мс. Это обрабатывает начальный запуск и остановку часов при опустошении очереди между предложениями. Дальнейшая привязка образцов использует устойчивую опорную метку; частый опрос getTimestamp на каждом 10-мс блоке убран. Для маршрута без меток остаётся оценка по позиции очереди.

Микрофон при подготовке вывода продолжает работать. Ручная остановка и отмена освобождают AudioTrack, включая отмену во время подготовки. Будущий эталон сброшенной очереди удаляется.

Официальная документация Android описывает нестабильность меток при запуске и рекомендует дождаться продвижения позиции: [AudioTrack.getTimestamp](https://developer.android.com/reference/android/media/AudioTrack#getTimestamp(android.media.AudioTimestamp)).

### Проверка источника перед активацией и отправкой

`AssistantSpeechEchoGuard` хранит ограниченный контекст озвучиваемых предложений: до 12 ссылок, до 3 секунд эталонного PCM на ссылку, окно пригодности 30 секунд после конца вывода. Это локальная память, без записи аудио или нового профиля владельца.

Контекст фиксируется в момент получения завершённого VAD-фрагмента по его времени захвата. Позднее распознавание сохраняет свою ссылку на эталон и не сравнивается с будущим ответом. Учтён хвост эха 400 мс и допуск времени 120 мс.

Перед обработкой имени, v3 и обычной команды голосовой отпечаток фрагмента сравнивается с отпечатком диктора из готового синтеза. Для этой проверки используется уже поставляемая модель SpeakerIdentifier. Дополнительная проверка владельца Voice ID сохраняет свою настройку и профиль.

- Сходство с диктором от 0.72 отклоняет фрагмент до события перебивания.
- Сходство до 0.35 считается отличающимся голосом; текст может повторять озвучку.
- При неопределённом результате, слишком коротком фрагменте или недоступной модели применяется проверка ASR: целиком совпавший фрагмент недавно воспроизводимого предложения отклоняется. Нормализуются регистр, пунктуация и «ё»; для слов от пяти букв допускается одна правка.

Это классификация источника, а не доказательство личности. Указанные пороги не являются результатом измерения FAR/FRR. При неопределённом результате намеренно повторённое пользователем слово из текущей озвучки может быть отклонено. Работа с одновременной речью пользователя требует отдельной практической проверки.

## Результаты

Физический Xiaomi `2201116SC`, Android API 33. Тот же тест со штатной озвучкой после исправления прошёл:

```text
captureSamples=421760
nonzeroReferenceSamples=238866
rawRms=0.08676766207992548
processedRms=0.008939232323927026
profile=WebRTC NS + AEC
commands=0
interruptions=0
errors=[]
```

В этом прогоне VAD не выделил фрагментов для распознавания (`guard.evaluated=0`): отсутствие самоперебивания подтверждено на работающем микрофоне и непустом эталоне. Ветки сравнения голоса и текста этим акустическим прогоном не проверены; их политика покрыта модульными тестами.

Сборка debug-приложения и тестового APK, lint и полный набор JVM-тестов успешны: 561 тест, 560 прошли, 1 пропущен, падений и ошибок нет. Новые модульные тесты проверяют голос диктора, отличающийся голос с повторением слова, короткое эхо, новый текст команды, хвост, будущий вывод, отложенный ASR и восстановление часов после паузы. SHA-256 собранного APK: `5a1602e605651b1fc46fd1f8a9db4735c4fcc137d1e434d629c5ee0d54ed45e4`.

### Практическая проверка голосом пользователя

15.10.2026 пользователь повторил сценарий обычного ввода с включёнными «Прерывать ответ голосом» и «Автовоспроизведение»: запрос о Солнечной системе, затем фраза «Проверка перебивания, ответь коротко» во время озвучки. Пользователь подтвердил: «Озвучка остановилась после моей фразы, фраза распознана».

Затем пользователь проверил «Активацию по имени»: во время озвучки сначала произнёс «Проверка без имени», затем команду «Ассистент, проверка перебивания, ответь коротко». Подтверждённый результат: «Без имени озвучка продолжилась; с именем остановилась, команда распознана».

В режиме «Персональное слово v3» пользователь проверил другое слово во время озвучки, затем записанное персональное слово и следующую отдельную команду. Подтверждённый результат: «На другое слово реакции нет; записанное слово остановило озвучку, команда распознана».

Это положительные результаты трёх ручных сценариев на подключённом Xiaomi. Задержка остановки, частота ошибок и решение конкретной ветки защитного фильтра в этих сценариях не измерялись. Отсутствие реакции на одну фразу без имени и одно постороннее слово не устанавливает частоту ложных активаций в других условиях.

| --- | --- |
| Штатный диктор, пользователь молчит | PASS: физический инструментальный тест, 0 команд и 0 прерываний |
| Обычный ввод: пользователь говорит во время озвучки | PASS по сообщению пользователя: озвучка остановилась, фраза распознана |
| Активация по имени: фраза без имени и команда с именем | PASS по сообщению пользователя: без имени озвучка продолжилась; с именем остановилась, команда распознана |
| Персональное слово v3 во время озвучки | PASS по сообщению пользователя: другое слово проигнорировано, записанное остановило озвучку, следующая команда распознана |
| Звук стороннего приложения и речь пользователя | Не прошёл по сообщению пользователя: собственная фраза не распозналась при звучащем YouTube. После попытки обнаружен режим NAME; запрошена подготовка повтора с проверкой DIRECT |

Повторная проверка файлов телефона обнаружила `no_backup/metric_kws_profile.bin`: файл персонального слова уже существует. Его наличие само по себе не подтверждает качество активации v3. Имя «Ассистент» определяется отсутствием сохранённого `custom_wake_word` и текущим значением по умолчанию в репозитории настроек.

Перед проверкой стороннего звука `dumpsys media_projection` вернул `null`, служба `PlaybackReferenceService` не обнаружена среди работающих служб приложения. Это состояние до включения пользователем, а не результат проверки качества подавления. Проверку стороннего звука следует проводить в обычном режиме, чтобы отсутствие команды нельзя было объяснить только ожиданием слова активации; речь стороннего приложения должна оставаться слышимой при работающем микрофоне.

После включения пользователь подтвердил сообщение «Включено на текущий сеанс. Обрабатывается только звук, доступный Android.» и выбрал YouTube. Через ADB подтверждена работа `PlaybackReferenceService` в foreground; `dumpsys audio` содержит сеанс приложения с источником `REMOTE_SUBMIX`, session 28361, UID 10496, `not silenced`. При этом `dumpsys media_projection` снова вернул `null`: по этому отдельному выводу работоспособность захвата не установлена. В журнале AudioRecord до получения результата сценария есть отметки `[mute]` для указанного сеанса; одновременное звучание YouTube на момент этих отметок не подтверждено. Наличие ненулевого эталона YouTube и качество подавления пока не установлены.

### Неуспешная попытка с YouTube и проверка условий

Пользователь сообщил: «Моя фраза не распозналась при звучащем YouTube». Успешное распознавание собственной речи на этом фоне не подтверждено.

При последующем чтении DataStore обнаружены `wake_word_enabled=true`, `wake_word_engine=LEGACY_ASR`, `audio_policy_revision=14`: текущий режим — NAME. В коде этого режима фраза без префикса «Ассистент» отклоняется при ожидании активации. Режим в момент самой неудачной фразы не зафиксирован, поэтому причинная связь с этой настройкой не установлена. Запрошена подготовка повтора: DIRECT, надпись «Команды без слова активации», слышимый YouTube, микрофон до проверки настроек выключен.

После попытки ADB подтвердил активный микрофонный сеанс `VOICE_RECOGNITION` 28561 (`silenced:false`) и регистрацию AudioMix для захвата. Для сеанса `REMOTE_SUBMIX` 28569 журнал AudioRecord содержит последовательные отметки `[mute]`, а текущий RecordActivityMonitor — `active? true`, `no config`. На момент чтения телефон находился в `Dozing`; эти сведения не устанавливают состав потока во время произнесённой команды.

Установленный `com.google.android.youtube` имеет UID 10193 и флаг `ALLOW_AUDIO_PLAYBACK_CAPTURE`. В истории его плееров указаны `USAGE_MEDIA` и `flags=0xA00`; это не содержит `FLAG_NO_MEDIA_PROJECTION` (0x400). Список `allowed capture policies` в прочитанном `dumpsys audio` пуст. Запрет захвата в этих проверенных признаках не обнаружен, но получение ненулевого звука ими не доказано. Правила допуска источников описаны в [документации Android](https://developer.android.com/media/platform/av-capture), значения флагов — в [исходнике AudioAttributes для Android 13](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-13.0.0_r1/media/java/android/media/AudioAttributes.java).
