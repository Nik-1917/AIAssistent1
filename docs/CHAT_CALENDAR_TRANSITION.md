# Переход из чата в календарь

Страница календаря и календарный чат используют одну переписку `calendar`. У обычного чата своя переписка `general`. При открытии календаря `ChatViewModel` публикует страницу, профиль и историю сообщений одним обновлением. Пока идёт анимация, Compose одновременно отображает входящий календарь и уходящий `ChatScreen`. Раньше этот экземпляр `ChatScreen` читал новое состояние напрямую и успевал показать календарную переписку на месте обычной.

Теперь `AIAssistantApp` передаёт состояние в `ChatScreen`. Пока чат открыт, он получает каждое обновление. Во время выхода он отображает последнее показанное состояние со своим заголовком и сообщениями. Compose освобождает ссылку на это состояние, когда убирает чат из композиции. Входящий календарь сразу получает актуальную сессию.

| Исходная страница | Что видно при выходе | Откуда входит календарь |
| --- | --- | --- |
| Чат | Заголовок «Чат» и обычная переписка | Слева |
| Календарный чат | Заголовок «Календарь» и календарная переписка | Справа |

## Проверка

В `CalendarNavigationInstrumentedTest` два сценария открывают календарь его кнопкой из соответствующего чата. В каждой истории есть своё контрольное сообщение. Тест продвигает часы анимации три раза по 64 мс. На каждом шаге он проверяет подпись профиля и содержимое переписки, а по изменению горизонтальной координаты кнопки возврата проверяет направление входа календаря.

На Redmi Note 11E Pro с Android 13 до исправления обычный чат уже на первом проверенном кадре показывал заголовок «Календарь». Контрольный переход из календарного чата проходил.

28 ноября 2026 года на том же телефоне оба теста прошли с исправленной сборкой. На трёх промежуточных кадрах каждого перехода отображались заголовок и сообщение исходного чата. Третий UI-тест подтвердил открытие календаря и возврат при работающей локальной модели. По отчётам Gradle прошли 914 модульных тестов, один пропущен.
