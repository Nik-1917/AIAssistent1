# Имя ассистента в настройках и хедере

Дополнение к независимым голосовым режимам, 2026-09-28.

## Поведение

- Начальное имя в хедере и поле «Имя ассистента» — **AI Assistant**. Существующее
  текстовое слово активации не переименовывает хедер при обновлении приложения.
- «Записать слово» / «Перезаписать слово» получает один фрагмент через существующий
  микрофон. Локальный ASR распознаёт его для имени, v3 сохраняет акустический
  отпечаток. После успешного сохранения имя появляется в поле и хедере.
- Поле «Имя ассистента» редактируется. «Сохранить имя» обновляет хедер. Очистка поля
  с сохранением возвращает AI Assistant. Имя сохраняется после перезапуска.
- В хедере первая буква имени заглавная: `алиса` → `Алиса`, `мой помощник` →
  `Мой помощник`. Остальные буквы сохраняются; `AI Assistant` не меняется.
  Форматирование действует и на ранее сохранённые имена, только при отображении:
  регистр текста в поле и настройках остаётся исходным.
- Эта правка не изменяет профиль слова, профиль Voice ID, порог v3, слово отдельного
  режима «Активация по имени», выбранный режим или окно ожидаемой команды.
- Новое произносимое слово v3 задаётся новой аудиозаписью. Удаление аудиопрофиля
  оставляет отображаемое имя; другой режим автоматически не включается.
- До 40 букв, цифр, пробелов, дефисов и апострофов. Результат ASR можно исправить
  вручную без перезаписи аудиослова. Распознаватель может ошибиться в написании имени.

## Разделение данных и сохранение

`assistant_display_name` — отдельная настройка отображения. Она не входит в
`AudioPreferences` / `VoiceInputPolicy`, не меняет `audio_policy_revision` и не
используется при распознавании слова или проверке владельца. `custom_wake_word`
остаётся настройкой отдельного режима активации по текстовому имени.

ASR добавлен только при регистрации слова для заполнения поля. При ожидании
слова v3 по-прежнему сравнивает аудиоотпечатки; текст хедера в решении не участвует.
Веса, MFCC, порог и формат файла профиля не изменены этим дополнением.

Пустой/невалидный результат ASR, ошибка модели и отмена до начала сохранения
оставляют прежние данные. При ошибке записи имени в DataStore после сохранения
нового профиля приложение пытается восстановить прежний профиль. Начавшееся
сохранение заканчивается без прерывания отменой. Это обработка ошибок в процессе,
а не обещание общей транзакции двух файлов при внезапном завершении процесса.
PCM очищается в `finally`; исходное аудио не сохраняется. Текст имени хранится
в настройках, отпечаток — в прежнем приватном файле.

## Проверка на телефоне

1. Без нового имени убедиться, что в хедере AI Assistant. Прежнее слово режима
   «Активация по имени» должно остаться прежним.
2. Остановить голосовой режим/конференцию, записать одно слово. Проверить, что
   распознанный текст появился в поле и хедере.
3. Выбрать v3 без Voice ID. Произнести записанное слово, дождаться сигнала и дать
   команду. Изменить только текст имени, сохранить. Проверить новый хедер и активацию
   по прежнему аудиослову. Переименование само по себе не регистрирует другое слово.
4. Повторить с включённым подготовленным Voice ID: правила проверки владельца
   должны сохраниться. Изменить имя между сигналом и командой — окно не сбрасывается.
5. Перезапустить приложение; проверить имя, профили и режим. Очистить поле имени
   и сохранить: хедер AI Assistant, аудиопрофиль прежний.
6. Проверить тишину, отказ разрешения и отмену записи. Прежние имя и профиль
   должны сохраниться. Удалить только слово: имя остаётся, выбранный v3 блокирует
   активацию до новой записи или явного выбора другого способа.

Физический микрофон и телефон этим дополнением пока не проверены.
