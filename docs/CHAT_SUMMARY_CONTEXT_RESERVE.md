# Контекст чата и выжимки: запас ответа 1024 токена

Изменение от 5 октября 2026 года.

## Поведение

Для `CHAT` и `SUMMARY` полный вход вместе с системной инструкцией и ChatML измеряется токенизатором выбранного GGUF. Перед началом ответа требуется `contextSize - promptTokens - 16 >= 1024`. Ровно 1024 допустимо. Это свободное место, а не требование к длине ответа: естественное завершение EOS сохраняется.

Сначала движок подбирает больший контекст с учётом GGUF и RAM и проверяет меньшие batch. Существующая рабочая аллокация учитывается при временно низкой оценке свободной памяти. Запасная конфигурация после неудачной аллокации также соблюдает порог 1024. Неудачная нативная загрузка не остаётся в состоянии Ready.

Календарный профиль сохраняет предыдущий расчёт: стартовый резерв 256, минимальный выход 64, выбор последнего пользовательского запроса, прежние batch и шаг расширения. Новые параметры истории не применяются к календарю.

## История чата

В рабочий контекст входит вся история активного обычного чата, кроме исключённых диалогов. Диалог — пользовательское сообщение и следующие за ним ответы ассистента до следующего пользовательского сообщения. Ответ без исходного вопроса не передаётся. Текущий запрос и системная инструкция не исключаются.

После невозможности расширить контекст пользователь выбирает «Освобождать автоматически» либо «Выбрать сообщения вручную». Причины ограничения RAM и предела модели различаются. Автоматический выбор исключает самые старые диалоги с повторной точной токенизацией после каждого исключения. Ручной выбор применяется целыми диалогами, после чего вход также проверяется заново.

Идентификаторы исключённых диалогов и предпочтение «Спрашивать меня» / «Автоматически исключать старые сообщения» сохраняются в отдельном DataStore `chat_context`, по chatId. По умолчанию приложение спрашивает. Галочка «В дальнейшем делать это автоматически» включает автоматическое поведение для следующих запросов. Таблица сообщений Room не меняется и не очищается этой функцией.

Выбор продолжает тот же запрос без повторного сохранения пользовательского сообщения. Ожидание не удерживает mutex движка и foreground-сессию генерации. Отмена, смена чата или модели отменяет ожидание; устаревший клик не может примениться к другому окну. Поток с уже показанным фрагментом ответа не запускается заново.

Разовый автоматический выбор действует до завершения текущего запроса, включая повторное снижение RAM. Галочка меняет поведение будущих запросов. При ручном выборе она не разрешает исключать дополнительные диалоги текущего запроса без нового выбора пользователя.

Если даже текущий запрос без старых диалогов не оставляет необходимого запаса, приложение сообщает об этом и сохраняет переписку. Обычный ответ чата больше не заменяется автоматически выжимкой.

## Выжимка

Бюджет каждого фрагмента рассчитывается с запасом 1024 и техническим запасом 16. Разбиение и объединение выполняются существующим LongTextSummarizer, который проверяет полный запрос токенизатором. Исходные фрагменты не исключаются как история чата. Если выполнить выжимку невозможно, исходная запись сохраняется; незавершённый результат не записывается как готовая выжимка.

Если память уменьшается уже во время обработки, при отказе до первого выходного фрагмента текущий исходный текст разбивается заново по меньшему бюджету. Обработанные соседние фрагменты остаются в дереве объединения; остаток исходника также обрабатывается. Частичный ответ не принимается за завершённую выжимку.
