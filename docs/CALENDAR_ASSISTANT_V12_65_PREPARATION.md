# V12.65: согласованность произнесённого времени

Подготовлено 4 октября 2026 года по подтверждённому плану.
**Данные, правила, оценщик и запуск обучения подготовлены. Обучение,
генерация новой моделью и создание GGUF не выполнялись.**

## Причина изменения

Сохранённый ответ Qwen3.5-2B содержит starts_at=2026-10-05T12:15,
но произносит «в двенадцать минут первого», то есть двенадцать минут,
а не пятнадцать. Правильный ответ: «в четверть первого».
Оба моста из `build/automatic_calendar_comparison.json` дали одинаковый
ошибочный текст. В V12.64 правильный эталон 12:15 уже присутствовал;
это не доказывает усвоение правила моделью.

Новые [правила V12.65](CALENDAR_ASSISTANT_V12_65_REPLY_CONSISTENCY.md)
подключены в `CALENDAR_ASSISTANT_TRAINING_SPEC.md`. Они явно разделяют
час, минуты начала, длительность, смещение и числа в названии.
Известное время произносится также в изменениях и неполных командах.

Полные запросы и JSON-ответы написаны вручную в
`docs/calendar_v12_65_manual/`. Программа сериализации не создаёт русские
предложения и не переставляет слова автоматически.

| --- | ---: | ---: | ---: |
| Train | 5857 | 92 | 5949 |

| Новый независимый holdout | 0 | 24 | 24 |

Всего в JSONL V12.65 7196 строк. Сохранены прежние контрольные наборы,
сетка 1440 минут суток и примеры относительных смещений V12.64.

Новые учебные строки:

- 60 абсолютных времён: четверть всех 24 часов; для 12 разных часов
  отдельные сопоставимые примеры минут 12, 14, 15, 16.
- 24 примера смещений и различения ролей чисел: минута, составные часы
  и минуты, перенос даты, длительность, число в названии, отсутствие
  известного времени и вопрос без создания события. Есть все шесть
  порядков названия, смещения и длительности для одного события.
- 8 изменений времени, включая 12:12, 12:14, 12:15, 12:16.

Новые validation и holdout отделены от train по формулировкам и названиям.
Holdout использует другие даты и названия; в разработческий набор не входит.
Это ограниченный контрольный набор, а не доказательство понимания всех
русских формулировок и всех сочетаний параметров.

## Исправления унаследованных ответов

Ручной реестр содержит 52 точных замены, применённые к 105 строкам:
82 train, 8 validation, 14 context_transfer_eval и 1 regression_holdout.
У 27 строк известное время не произносилось; остальные 78 содержали
устаревшие формулировки. Не все эти случаи являются неверной минутой:
часть старых форм численно верна, часть не распознавалась прежним сканером.

Изменены reply и метка contract_version этих 105 копий с v12.1 на v12.57.
Переход метки нужен для применения действующего контракта произнесения
времени; старый v12.1 требовал только название при создании события.
Intent, params, исходные запросы, system и идентификаторы сохранены.
Полный перечень: `docs/calendar_sft_v12_65/correction_log.json`.
Исходные V12.64 и предыдущие версии не перезаписаны.
Остальные 6959 унаследованных строк побайтно совпадают с V12.64.

## Оценивание и следующее обучение

`v12_65_evaluation.py` отдельно проверяет параметры относительно эталона,
смысл времени в reply, согласованность с фактически выданными параметрами,
стиль и арифметику смещения. Правильные параметры при неверном reply
не дают зачёт. Ошибочная пара, где reply совпадает с ошибочными params,
тоже не проходит проверку относительно эталона.

Точные названия и именованные цели изменений исключаются из разбора
времени события. Проверяются оба конца интервала. Проверяющий код
распознаёт документированные формы времени; это не универсальный
анализатор произвольного русского текста и не код Android.

`train_v12_65.py` явно использует папку V12.65 и новый оценщик.
Настройки находятся в `v12_65_training_config.json`: исходная Qwen3.5-2B,
QLoRA rank 32 / alpha 64, 3 эпохи, learning rate 0.0001, эффективный
batch 16, microbatch 4, длина 384. Это подготовленная конфигурация,
а не доказанные оптимальные параметры.

Каждая строка обучает только assistant JSON и конец сообщения. По строкам
чередуются стандартный ChatML, транспорт Android и фактический короткий
system Android с теми же датой и временем. Русские запросы и ответы
сохраняются. Нет добавленного thinking-префикса или текста правил в system.

В выборе контрольной точки участвуют 96 разработческих примеров в двух
вариантах запроса, всего 192. Оценка сначала учитывает средний полный
зачёт по intent, затем согласованность времени, затем точность params.
Метаданные относительных смещений передаются оценщику. Holdout не
используется для выбора. Точки оценки: 186, 372, 558, 744, 930, 1116;
перед каждой сохраняется восстанавливаемый checkpoint.

## Выполненные проверки и границы

- Повторная сборка V12.65 и проверка происхождения данных проходят.
  Хеши 1145 защищённых исходных файлов соответствуют началу этой подготовки.
- Все 5455 строк JSONL с известным временем прошли проверку reply.
  Все 192 эталонных разработческих варианта проходят новый оценщик.
- Для локального токенизатора Qwen3.5-2B проверено 7196 строк в трёх
  вариантах, всего 21588 кодирований. Максимум 216 / 219 / 211 токенов
  при лимите 384; обрезаний нет, маска assistant-only корректна.
- Подготовительный запуск train_v12_65.py --mode preflight прошёл.
  Он проверил исходные файлы модели, данные, токенизацию и конфигурацию;
  веса для обучения или генерации не загружались.
- Сохранённые ответы automatic и legacy заново оценены: параметры
  правильны, reply не проходит. Исправленный эталон проходит. Это
  повторная оценка известных ответов, не новое выполнение модели.
- Подготовлены 48 запросов для 24 независимых holdout-примеров в двух
  вариантах prompt. Генерация ответов на них ещё не выполнялась.
- Все 27 новых тестов прошли. Они проверяют подмену минут часом, соседние минуты, четверти,
  начало/окончание, неизвестное время, названия, смещения, разделение
  выборок, выбор checkpoint и привязку сохранённого ответа к запросу.

Исторический тест повторной сборки V12.64 требует снимок прежнего проекта.
В текущем checkout его хеши не совпадают с 31 Android-файлом, изменённым
до этой работы, и с разрешённым изменением TRAINING_SPEC в V12.65.
Старый тест и его реестр не ослаблялись ради зелёного результата.
Проверка текущей V12.65 использует собственный реестр и проходит.
Общий прогон: 73 теста, 72 прошли, один исторический тест завершился ошибкой
несовпадения снимка. Из 72 прошедших 27 относятся к V12.65 и 45 к прежним
проверкам арифметики, речи и оценивания.
Подробные результаты тестов: `build/calendar_v12_65_preparation/tests.json`.

Материалы проверки: `build/calendar_v12_65_preparation/`, подготовительный
отчёт обучения: `build/calendar_v12_65_qwen35/qwen35_2b/preflight.json`.
Поведение следующего обученного адаптера, GGUF и приложения пока не измерено.

## Команды

Из корня проекта, без обучения:

```powershell
python -X utf8 -B tools/calendar_sft/prepare_v12_65.py --check-only
python -X utf8 -B -m unittest discover -s tools/calendar_sft -p test_v12_65.py -v
.\build\calendar_sft_qwen35_venv\Scripts\python.exe -X utf8 -B tools/calendar_sft/train_v12_65.py --mode preflight
```

Будущие команды после решения запускать обучение:

```powershell
.\build\calendar_sft_qwen35_venv\Scripts\python.exe -X utf8 -B tools/calendar_sft/train_v12_65.py --mode smoke
.\build\calendar_sft_qwen35_venv\Scripts\python.exe -X utf8 -B tools/calendar_sft/train_v12_65.py --mode train
```

Обучение использует отдельную выходную папку. Старые скрипты обучения,
адаптеры и GGUF не переключены и не перезаписаны. У нового скрипта режим
по умолчанию preflight. Smoke, полное обучение и сборка GGUF в этой работе
не запускались; GPU-путь этой версии требует проверки перед обучением.
