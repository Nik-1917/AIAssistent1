# Сохранение текста в основном поле ввода

Дата: 19.10.2026.

## Поведение

- Неотправленный текст автоматически записывается в локальный DataStore `chat_input_draft` при редактировании и загружается при следующем запуске приложения.
- Текст сохраняется целиком: пробелы, пустые строки, переносы, эмодзи и содержимое длиннее лимита отправки. Ограничения длины по-прежнему проверяются при отправке; сохранение не обрезает ввод.
- Закрытие и повторное создание панели, переход на другой экран, пересоздание Activity и переключение режима чата не очищают поле. Основное поле остаётся общим для обычного и календарного режима.
- Нажатие отправки очищает черновик только если `sendMessageInternal` принял сообщение. При отказе принять запрос текст остаётся. Это момент принятия запроса, а не успешного окончания генерации ответа.
- Ручное удаление всего текста также сохраняется: старый черновик не должен появляться при следующем запуске.
- Голосовой черновик и карточки календарных событий продолжают использовать собственные хранилища. Очистка истории и остановка генерации не удаляют основной текстовый черновик.

## Реализация и защита от потери текста

`InputPanel` получает текст и обработчик изменения из `ChatViewModel`; локальное `remember` больше не является владельцем текста. `ChatInputDraftController` создаётся один раз в `AppModule` и работает в области корутин приложения. Поэтому закрытие Activity или ViewModel не отменяет уже поставленную запись.

Один обработчик последовательно записывает изменения. Если накопились правки во время медленной записи, очередь оставляет самое новое состояние. Очистка проходит через ту же очередь, поэтому старая запись не может завершиться после новой и восстановить удалённый текст. Задержки для ожидания окончания набора нет.

До завершения загрузки редактирование и отправка основного поля недоступны: начальное пустое состояние не перезаписывает сохранённый черновик. Ошибка чтения не подменяется пустым текстом. При ошибке чтения или записи рядом с полем появляется сообщение и кнопка «Повторить». Уход в фон дополнительно повторяет сохранение текущего состояния, сохраняя существующую обработку голосового черновика.

Запись асинхронная. После успешной записи данные доступны при новом запуске и после перезагрузки телефона. Последняя правка, для которой запись ещё не завершилась перед внезапной потерей питания или принудительным завершением процесса, не имеет гарантии сохранения.

## Проверки

Добавлены проверки реального файла DataStore: закрытие и повторное открытие, длинный текст без обрезки, ввод только из пробельных символов и удаление черновика. Проверки контроллера покрывают загрузку, отправку с отказом/принятием, порядок медленных записей, новый текст после отправки, ошибки чтения/записи и завершение подписки экрана.

Первый запуск и отдельный повтор теста очистки выявили ошибку замены существующего файла в Windows (`Unable to rename ...preferences_pb.tmp`). В исходниках DataStore 1.1.7 проверена зависимость `FileStorage` от Android SDK: локальная Android-заглушка выбирает `File.renameTo`, тогда как на поддерживаемом приложением Android API 30+ используется `Files.move(..., REPLACE_EXISTING)`. Для повторной записи в этом JVM-тесте используется штатный `OkioStorage` с реальным файлом; результат затем открывается через `FileStorage`. Рабочее хранилище приложения из-за этой особенности тестов не менялось.

- Итоговый запуск `:app:testDebugUnitTest :app:assembleDebug :app:compileDebugAndroidTestKotlin :app:lintDebug --offline --console=plain '-Pkotlin.compiler.execution.strategy=in-process'` — успешно.
- Модульные тесты: 709 обнаружено, 708 прошло, 1 пропущен (`CalendarPromptContractTest`), ошибок и падений нет. Все 11 новых проверок хранилища и контроллера прошли.
- Lint: 0 ошибок, 58 предупреждений, 2 подсказки.
- Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.
- `git diff --check` — без ошибок.
- UI-тесты скомпилированы, но не запускались. APK на телефон не устанавливался; восстановление после физической перезагрузки телефона пока не проверено.

## Проверка на телефоне

1. Ввести многострочный текст, свернуть приложение и открыть снова.
2. Перейти на другой экран и обратно; скрыть и показать панель; проверить оба режима чата.
3. Закрыть приложение и открыть заново; затем повторить проверку с перезагрузкой телефона.
4. Удалить текст вручную и перезапустить приложение: поле должно остаться пустым.
5. Отправить сообщение, затем перезапустить приложение: принятый текст не должен возвращаться в поле.
